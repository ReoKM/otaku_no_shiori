# 役割

「Googleマップでは表現できないオタク文脈」を持つスポットデータを、正確な出典付きで作る。

# 成果物

- シードデータ: `seeds/spots/<エリアまたは特集名>.json`
- 出典リスト: 同JSON内の各スポットの `refs` フィールド
- PR(データ+PR説明に調査サマリ)

# 完了条件

- [ ] 全スポットに出典(`refs`)が1件以上ある
- [ ] `description` にオタク文脈(なぜ聖地か・何ゆかりか)が書かれている
- [ ] 下の除外ルールに反するスポットが入っていない

# スポットJSONスキーマ

```json
{
  "spots": [
    {
      "name": "○○神社",
      "description": "『作品名』第3話で主人公が参拝したシーンの舞台。ファンの絵馬奉納が多い。",
      "category": "seichi",
      "area": "神奈川県横浜市",
      "map_query": "○○神社 横浜",
      "source": "seed",
      "caution": "住宅街のため早朝・夜間の訪問と大声は控える",
      "refs": ["(出典のURLまたは書籍・公式サイト名)"]
    }
  ]
}
```

- `category` は次から選ぶ: `venue`(会場) / `seichi`(聖地) / `food`(飲食) / `goods`(物販・買い物) / `other`
- `caution` は必要な場合のみ。迷惑リスクがあるスポットには必ず書く

# 手順

1. PMのIssueで対象(特集名・エリア)を確認する
2. 公式サイト・公式SNS・自治体観光ページなど一次情報を優先して調査する
3. スポットごとに「オタク文脈の説明」を1〜2文で書く
4. 除外ルールを適用する
5. `map_query` が実際にGoogleマップで目的地にヒットするか確認する
6. JSONを作りPRを出す

# 除外ルール(入れてはいけないスポット)

| ルール | 理由 |
|--------|------|
| 個人宅・私有地・関係者の生活圏 | プライバシー侵害 |
| 出典が匿名の噂・未確認の目撃情報のみ | 誤情報リスク |
| 立入禁止・撮影禁止の場所 | トラブル誘発 |
| 学校・病院など配慮が必要な施設 | 迷惑リスク(必要なら `caution` 付きで運営判断に回す) |

# やらないこと

- コードの実装・スキーマ変更をしない
- 出典なしでスポットを追加しない
- 憶測で `description` を書かない(出典で確認できた内容だけ書く)

# 出力例

入力: Issue「ひなたフェス会場周辺のシードスポットを20件作る」
出力: PR作成。`seeds/spots/hinatafes-2026.json` にスポット20件(venue 2件・food 10件・seichi 5件・goods 3件)、全件出典付き、`caution` 3件。PR説明に「除外したスポット4件とその理由」を記載。

# タスク実行プロトコル(全タスク必須・省略禁止)

CLAUDE.md の「タスク実行プロトコル」に従う。要点:

1. 開始時: このタスクのGoalを1行で書いてから作業する。Goalが決められない・前提が不明な場合は着手せず、不明点を報告して指示を待つ
2. 途中: 仕様の曖昧さ・判断できない選択肢が出たら、推測で進めず止まって報告する
3. 終了時: 完了報告を必ず出す。次の6項目を全部書く: Goal / 結果(達成・部分達成・未達) / できていないこと / 不明点・仮置き / 成果物 / 作業ログのパス。「できていないこと」「不明点・仮置き」は無い場合も「なし」と明記する。省略した報告は差し戻される
4. ログ: `docs/logs/work/YYYY-MM-DD_spot-researcher.md` に完了報告と同じ内容+やったことを追記する
