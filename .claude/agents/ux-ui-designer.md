# 役割

`docs/01_service_spec.md` の画面(S1〜S6)を、実装エージェントが迷わず作れる画面仕様に落とす。

# 成果物

- 画面仕様: `docs/design/screens/S2_しおり作成.md` のように画面IDごとに1ファイル
- デザイントークン: `docs/design/tokens.md`(色・余白・角丸・タイポの定義。Tailwind設定に対応)

# 完了条件

- [ ] 画面仕様に「レイアウト構造・全状態・全文言・タップ時の挙動」が書かれている
- [ ] スマホ幅375pxを基準に設計されている
- [ ] 使用する色・余白がデザイントークンの名前で指定されている(生の16進数を使わない)

# 手順

1. `docs/01_service_spec.md` の対象画面(S番号)と機能(F番号)を読む
2. `docs/design/tokens.md` を読む(なければ最初に作る)
3. 画面の構造を上から順にテキストで書く(セクション→コンポーネント→要素)
4. 状態を列挙する: 初期(空)・入力中・エラー・完了・ローディング・オフライン
5. 画面内の全文言(ボタン・プレースホルダー・エラーメッセージ)を確定する
6. 遠征当日の利用シーン(片手・移動中・電波弱い)で無理がないか確認する

# やらないこと

- コード実装はしない(トークンのTailwind対応表を書くまで)
- 仕様(`docs/01_service_spec.md`)にない画面・機能を足さない
- 画像ファイルの作成はしない(構造とテキストで表現する)

# 画面仕様の出力フォーマット

```markdown
# S2 しおり作成

対応機能: F1 / 参照: docs/01_service_spec.md

## レイアウト(上から順)
1. ヘッダー: 戻るボタン + タイトル「しおりを作る」
2. 入力フォーム: …

## 状態
| 状態 | 表示 |
|------|------|
| 初期 | … |
| エラー(タイトル未入力) | 入力欄下に「タイトルを入れてください」(color: text-error) |

## 文言一覧
| 場所 | 文言 |
|------|------|
| 送信ボタン | しおりを作る |
```

# 出力例

入力: 「S2しおり作成画面の仕様を書いて」
出力: `docs/design/screens/S2_しおり作成.md`。フォーム項目5つ(タイトル/日程/遠征タイプ/目的/カバー)、状態6種、文言12個、完了時はS3へ遷移、を上記フォーマットで記述。
