# sns-draft — 週次SNS投稿カレンダー生成

## 役割1行

オーナーがコピペ投稿するだけの状態の、翌週分投稿カレンダーを作る。

## 成果物

`docs/sns/YYYY-Www.md`(翌週の週番号。例: `docs/sns/2026-W30.md`)

## 完了条件

- [ ] 投稿5〜7件。各投稿に本文・画像案・投稿日時・目的がある
- [ ] 本文は140字以内。絵文字は1投稿2個まで
- [ ] 3本柱(機能紹介/お役立ち/イベント連動)の配分が お役立ち:宣伝=2:1 に近い

## 手順

1. `docs/04_growth_monetization.md` の「投稿の型」とトーン規約を読む
2. 前週カレンダー(`docs/sns/` の最新ファイル)の振り返りを読む(なければスキップ)
3. PMの週次計画(`docs/plans/` の最新)からリリース・イベント予定を拾う
4. 投稿5〜7件を下のフォーマットで書く
5. sns-writer の禁止事項(権利画像・断定・比較攻撃・便乗)に反していないか自己確認する
6. ファイル末尾に前週の振り返り欄(投稿ごとの反応メモ用の空表)を付ける

## 出力フォーマット

```markdown
# SNS投稿カレンダー YYYY-Www

## 投稿一覧
### 1. (火) 21:00 — お役立ち
- 本文: 遠征の持ち物、毎回ゼロから思い出してませんか?🎒 ライブ遠征の定番リストを画像にまとめました。保存して使ってください
- 画像案: 持ち物チェックリスト画像(share-image-designerに依頼 or 既存素材名)
- 目的: 保存数・プロフィールクリック

### 2. …

## 前週の振り返り(投稿後に記入)
| 投稿 | インプ | 保存/RT | メモ |
|------|--------|---------|------|
```

## やらないこと

- 投稿の実行・予約(オーナーだけが投稿する)
- 権利のある画像(アーティスト写真・作品ロゴ)を画像案に指定しない
- 未確定情報(日程・価格)を断定で書かない

## 出力例

入力: `/sns-draft`
出力: `docs/sns/2026-W30.md`。投稿6件(お役立ち3・機能紹介2・告知1)、うち1件はW30のリリース予定(共有画像テンプレ追加)に連動。
