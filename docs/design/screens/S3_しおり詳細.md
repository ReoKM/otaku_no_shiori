# S3 しおり詳細(タブシェル共通)

対応機能: F1(詳細シェル)/ F2・F3(タブ内容は`S3a_持ち物.md`・`S3b_TODO.md`参照) / 参照: `docs/01_service_spec.md`
ルーティング: `/shiori/[id]/packing`(S3a・持ち物) / `/shiori/[id]/todo`(S3b・TODO) / 旅程・ログタブはW1では準備中表示のみ(専用ルートは未確定。タブ切替のみで実装可、frontend-dev裁量)
デザイントークン: `docs/design/tokens.md`

このファイルは4タブ共通の「シェル」(ヘッダー+タブバー)の仕様。各タブの中身は`S3a_持ち物.md`(持ち物)・`S3b_TODO.md`(TODO)を参照。旅程/ログの2タブはW1では中身を実装せず「準備中」表示のみとする。

※2026-07-11オーナー決定: スポット(F5)は独立タブにせず、旅程タブ(S3c)内のセクションとして扱う(`docs/01_service_spec.md`参照)。旅程タブ内の構成はW2のUI設計で確定する。

## レイアウト(上から順)

1. **ヘッダー**(タブバーとまとめて`sticky top-0`、背景`paper-surface`)
   - 縦スクロール量が36pxを超えるとコンパクト表示に切り替える: タイトルを22px/2行から17px/1行に縮め、日程を隠し、上下パディングを詰める。12px未満まで戻すと通常表示に戻す(境界でのちらつきを防ぐため縮め/戻しで閾値を分ける)
   - 右端は「共有画像を作る」への遷移をアイコンボタン(44×44px、`aria-label="共有画像を作る"`)で置く
   - 左: 戻るボタン(`<`アイコン、44×44pxタップ領域) → S1(`/`)へ遷移
   - 中央: しおりタイトル(`text-heading-lg`、1行省略`truncate`)
   - タイトル下に小さく日程(`text-body-sm` / `color-text-secondary`): 「2026/08/01〜2026/08/02」
2. **タブバー**(ヘッダー直下に固定、横4分割、高さ48px、背景`paper-surface`、下境界`paper-border`)
   - 選択中は`sakura-ink`の太字+下辺3pxの`sakura`インクバー。非選択は`ink-strong`の中太
   - 持ち物 / 準備 / 旅程 / 記録 の4タブ
   - 表示名はリニューアルデザインに合わせた。`todo`タブはオーナー指示で「やること」→「準備」に変更(タブ内が「やること」/「費用」の2セグメントになったため、上位タブ名は両方を含む語にする)。URLパス(`/todo`・`/log`)は既存リンクとService Workerのキャッシュルーティングを壊さないため据え置く
   - 選択中タブ: 文字`color-primary`+下線2px`color-primary`
   - 未選択タブ: 文字`color-text-secondary`
   - 「旅程」「ログ」の2タブは選択可能(タップでき、準備中画面が開く)。タブ自体をグレーアウトしない(将来実装時に見た目を変えなくて済むようにするため)
3. **タブコンテンツエリア**
   - 持ち物タブ: `S3a_持ち物.md`参照
   - TODOタブ: `S3b_TODO.md`参照
   - 旅程/ログタブ: 「準備中」ブロック(下記参照)

## コンポーネント構造

```
<Header>
  <BackButton />
  <ShioriTitleBlock title date />
</Header>
<TabBar activeTab>
  <Tab id="packing" label="持ち物" />
  <Tab id="todo" label="準備" />
  <Tab id="itinerary" label="旅程" />
  <Tab id="log" label="記録" />
</TabBar>
<TabContent>
  {activeTab === "packing" && <PackingTab />}   // S3a_持ち物.md
  {activeTab === "todo" && <TodoTab />}         // S3b_TODO.md
  {activeTab === "itinerary" && <ComingSoon feature="旅程" />}
  {activeTab === "log" && <ComingSoon feature="ログ" />}
</TabContent>
```

### ComingSoon(準備中ブロック、旅程/ログ共通)

- 画面中央に配置(上下`space-10`の余白)
- アイコン代わりの絵文字(`text-heading-lg`サイズ、装飾のみ): 「🚧」
- 見出し(`text-heading-md`): 「{機能名}は準備中です」
- 説明文(`text-body-sm` / `color-text-secondary`): 「近日公開予定です。もうしばらくお待ちください。」
- ボタン等の操作要素は置かない

## 状態

| 状態 | 表示 |
|------|------|
| ローディング(IndexedDBから該当`shiori`読込中) | ヘッダーのタイトル部分をスケルトン(`color-bg-disabled`のブロック)にする。タブバーは表示するが押下不可とし、操作不能であることが視覚的に伝わるようタブバー全体を`opacity-50`でグレーアウトする(押しても反応しない状態を通常時と同じ見た目で放置しない) |
| 通常表示 | ヘッダーに実際のタイトル・日程、選択中タブの内容を表示 |
| 該当しおりが存在しない(不正なid・削除済み) | タブコンテンツエリアに「このしおりは見つかりませんでした」(`color-error`)+「一覧に戻る」ボタン(`/`へ遷移)。ヘッダーのタイトルは「しおりが見つかりません」と表示 |
| 準備中タブ表示中 | ComingSoonブロックを表示(上記) |
| オフライン | データはIndexedDBのローカル参照のみのため通信不要。オフライン専用の表示分岐は無し |

## タップ時の挙動

| 要素 | 挙動 |
|------|------|
| 戻るボタン | `/`(S1)へ遷移 |
| 持ち物タブ | `/shiori/[id]/packing`へ遷移(タブ切替) |
| TODOタブ | `/shiori/[id]/todo`へ遷移(タブ切替) |
| 旅程/ログタブ | 同一シェル内でComingSoonブロックを表示する(専用ルートを割り当てるかはfrontend-dev裁量。W1ではルーティング未確定のため、タブ状態のみで切り替える実装でよい) |
| 「一覧に戻る」ボタン(しおりが見つからない場合) | `/`(S1)へ遷移 |

## 文言一覧

| 場所 | 文言 |
|------|------|
| タブラベル | 持ち物 / 準備 / 旅程 / 記録 |
| 準備中見出し | {機能名}は準備中です(例: 旅程は準備中です) |
| 準備中説明文 | 近日公開予定です。もうしばらくお待ちください。 |
| しおり未検出時のヘッダー | しおりが見つかりません |
| しおり未検出時の本文 | このしおりは見つかりませんでした |
| しおり未検出時のボタン | 一覧に戻る |

## 遠征当日の利用シーン確認

- 持ち物・TODOタブは遠征当日に片手で確認する画面のため、タブバーのタップ領域は44px以上を確保し、タブ切替だけで完結させる(モーダルやスクロール階層を増やさない)
- 通信不要(IndexedDBのみ)で全タブ・全状態が成立する
