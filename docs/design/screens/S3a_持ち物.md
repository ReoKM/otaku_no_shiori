# S3a 持ち物(持ち物タブ)

対応機能: F2 / 参照: `docs/01_service_spec.md`
ルーティング: `/shiori/[id]/packing`(タブシェルは`S3_しおり詳細.md`参照)
デザイントークン: `docs/design/tokens.md`

## 前提: テンプレ自動投入のタイミング(アーキテクト確定仕様)

- 持ち物タブを**初めて開いた時点**でデータが0件なら、そのしおりの`trip_type`に対応するテンプレート(`docs/01_service_spec.md`のF2、遠征タイプにつき1種)を自動投入する
- ユーザーが全項目を削除して0件に戻った場合は**自動再投入しない**。空状態に「テンプレから追加」ボタンを表示し、手動操作でのみ再投入する
- 実装上の注意(frontend-dev向け): 「0件かどうか」だけでは"初回"と"全削除後"を区別できないため、しおりごとに**テンプレ投入済みフラグ**を別途保持すること(例: IndexedDB上の`shiori`レコードに`packingTemplateSeeded: boolean`を持たせる等、guest保存のデータ設計は`src/lib`側で決めてよい)。フラグが立っていない場合のみ自動投入し、フラグが立っている場合は0件でも自動投入しない

## レイアウト(上から順、タブシェル内のコンテンツ領域)

1. **ツールバー行**(左右余白`space-4`、高さ44px以上)
   - 左: 件数表示(`text-body-sm` / `color-text-secondary`): 「8件」
   - 右: 「並べ替え」テキストボタン(項目が2件以上の時のみ表示。並べ替えモード中は「完了」に文言変化)
2. **リストエリア**(縦スクロール、項目間`color-border-default`の1px区切り線)
   - 0件の場合: `EmptyPacking`ブロック
   - 1件以上の場合: `PackingRow`を`sort_order`昇順で縦積み
3. **手動追加フォーム**(`sticky bottom-0`、背景`color-bg-surface`、上境界`color-border-default`、内側パディング`space-4`)
   - テキスト入力(プレースホルダー「例: モバイルバッテリー」)+「追加」ボタン(横並び、入力欄は幅可変・ボタンは固定幅)

## コンポーネント構造

```
<PackingTab>
  <Toolbar count={items.length} sortMode onToggleSort />
  <List>
    {items.length === 0
      ? <EmptyPacking onAddFromTemplate />
      : items.map(item => (
          sortMode
            ? <PackingRowSortMode item={item} onMoveUp onMoveDown />
            : <PackingRow item={item} onToggleCheck onEdit onDelete />
        ))}
  </List>
  <AddForm onAdd={label => ...} />
</PackingTab>
```

### PackingRow(通常モード、1行)

横並び、行高さ56px以上、左右余白`space-4`:

1. チェックボックス(44×44pxタップ領域、`radius-sm`)。タップで`is_checked`をトグル
2. ラベル(`text-body`、flex-grow、1〜2行まで、はみ出しは`truncate`)
   - `is_checked=true`のとき: 打ち消し線+`color-text-muted`
   - `is_checked=false`のとき: 通常の`color-text-primary`
3. 編集ボタン(鉛筆アイコン、44×44pxタップ領域)
4. 削除ボタン(ゴミ箱アイコン、44×44pxタップ領域)

### PackingRow(編集中)

編集ボタン押下後、ラベル部分がテキスト入力に置き換わり、右側のアイコンが「保存(✓)」「キャンセル(×)」に変わる(いずれも44×44px)。

### PackingRow(削除確認中)

削除ボタン押下後、行右側の編集/削除アイコンが「本当に削除しますか？」(`text-caption`)+「削除」(`color-error`文字)+「キャンセル」の2ボタンに置き換わる(モーダルは使わずインラインで完結させる)。

### PackingRowSortMode(並べ替えモード、1行)

1. 上矢印ボタン(44×44px)。先頭の項目は無効化(`color-text-disabled`表示、タップ不可)
2. 下矢印ボタン(44×44px)。末尾の項目は無効化
3. ラベル(タップ操作不可、表示のみ、`color-text-primary`)

チェックボックス・編集・削除は並べ替えモード中は非表示にする(誤操作防止)。

### EmptyPacking(空状態)

- 説明文(`text-body` / `color-text-secondary`): 「まだ持ち物がありません」
- ボタン(`color-primary`背景、`radius-md`): 「テンプレから追加」
  - タップすると、しおりの`trip_type`に対応するテンプレート項目一式を`sort_order`0番から追加する
  - 追加後は通常のリスト表示に切り替わる

### AddForm(手動追加フォーム)

- テキスト入力: プレースホルダー「例: モバイルバッテリー」、文字数上限30文字(仮置き。`docs/design/screens/S2_しおり作成.md`のタイトル上限と揃えた)
- 「追加」ボタン: 入力を`trim()`(前後の半角・全角スペース除去)した結果が空の場合はタップしても追加せず、入力欄に「持ち物の名前を入れてください」(`color-error`)を表示する。保存時もトリム後の文字列を保存する(空白のみの項目が並ぶことを防ぐ。編集保存時も同じ扱い)
- 追加成功時: 新しい項目を`is_checked=false`・現在の最大`sort_order`+1で末尾に追加し、入力欄を空にしてフォーカスを維持する(連続入力しやすくするため)

## 状態

| 状態 | 表示 |
|------|------|
| ローディング | リストエリアに`color-bg-disabled`のスケルトン行を3本表示 |
| 空(初回・テンプレ投入前) | 通常は自動投入が即時実行されるため一瞬で「一覧あり」に遷移する。投入処理自体が失敗した場合のみ次の「空(全削除後)」と同じ表示にフォールバックする |
| 空(全削除後、テンプレ投入済みフラグはtrueだが0件) | `EmptyPacking`ブロックを表示(「まだ持ち物がありません」+「テンプレから追加」ボタン)。手動追加フォームは通常どおり表示し続ける |
| 一覧あり(通常モード) | `PackingRow`を`sort_order`昇順で表示。チェック済み項目も同じ位置に残す(完了項目を末尾へ移動する仕様は無い) |
| 並べ替えモード | ツールバー右ボタンが「完了」に変化。全行が`PackingRowSortMode`表示になる |
| 行編集中 | 該当行のみラベルがテキスト入力になる。他の行は通常表示のまま |
| 行削除確認中 | 該当行のみ確認UIになる。他の行は通常表示のまま |
| 追加フォーム入力エラー | 入力欄下に「持ち物の名前を入れてください」(`color-error`) |
| オフライン | データはIndexedDBのローカル参照のみのため通信不要。オフライン専用の表示分岐は無し |

## タップ時の挙動

| 要素 | 挙動 |
|------|------|
| チェックボックス | `is_checked`をトグルしIndexedDBへ即時保存(保存ボタン不要) |
| 編集(鉛筆)ボタン | その行を編集モードにする |
| 編集中の保存(✓) | 入力値(空でなければ)でラベルを更新し通常表示へ戻る。空の場合は保存せず「持ち物の名前を入れてください」を表示 |
| 編集中のキャンセル(×) | 変更を破棄し通常表示へ戻る |
| 削除(ゴミ箱)ボタン | その行を削除確認状態にする |
| 削除確認中の「削除」 | 項目を削除し、以降の項目の`sort_order`を詰める |
| 削除確認中の「キャンセル」 | 通常表示へ戻る(削除しない) |
| ツールバーの「並べ替え」 | 並べ替えモードへ切り替える |
| 並べ替えモードの「完了」 | 通常モードへ戻る(この時点の並び順をそのまま保持) |
| 上矢印ボタン | その項目と1つ上の項目の`sort_order`を入れ替える |
| 下矢印ボタン | その項目と1つ下の項目の`sort_order`を入れ替える |
| EmptyPackingの「テンプレから追加」 | `trip_type`対応テンプレート項目一式を追加する |
| AddFormの「追加」 | 入力値をバリデーションし、問題なければ末尾に新規項目を追加する |

| ツールバーの並べ替えボタン(並べ替え中) | 完了 |
| 空状態の説明文 | まだ持ち物がありません |

| 削除確認の文言 | 本当に削除しますか？ |

## 遠征当日の利用シーン確認

- 当日はチェック操作が中心。チェックボックスは44×44px確保し、片手の親指操作でも押しやすい位置(行の左端固定)にする
- 並べ替え・編集・削除は事前準備段階での操作を想定し、当日はチェックのみで完結できる構造にした
- 通信不要(IndexedDBのみ)で全操作が成立する
