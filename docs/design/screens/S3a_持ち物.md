# S3a 持ち物(持ち物タブ)

対応機能: F2 / 参照: `docs/01_service_spec.md`
ルーティング: `/shiori/[id]/packing`(タブシェルは`S3_しおり詳細.md`参照)
デザイントークン: `docs/design/tokens.md`

## 前提: テンプレ自動投入のタイミング(アーキテクト確定仕様)

- 持ち物タブを**初めて開いた時点**でデータが0件なら、そのしおりの`trip_type`に対応するテンプレート(`docs/01_service_spec.md`のF2、遠征タイプにつき1種)を自動投入する
- ユーザーが全項目を削除して0件に戻った場合は**自動再投入しない**。空状態に「テンプレから追加」ボタンを表示し、手動操作でのみ再投入する
- 実装上の注意(frontend-dev向け): 「0件かどうか」だけでは"初回"と"全削除後"を区別できないため、しおりごとに**テンプレ投入済みフラグ**を別途保持すること(例: IndexedDB上の`shiori`レコードに`packingTemplateSeeded: boolean`を持たせる等、guest保存のデータ設計は`src/lib`側で決めてよい)。フラグが立っていない場合のみ自動投入し、フラグが立っている場合は0件でも自動投入しない

## レイアウト(上から順、タブシェル内のコンテンツ領域)

左右余白は`space-6`(24px)。進捗・件数・リストの左端をすべて揃える。

1. **準備状況カード**(`paper-surface`背景、`paper-border`枠線、`radius-lg`、内側`px-4 py-3.5`)
   - 左: 「準備状況」(`text-label` / `ink-label`)
   - 右: 「n／m完了　残りn件」(`text-body-sm`。1件以上完了していれば`sakura-ink`、0件なら`ink-sub`)。0件のときは「登録0件」
   - 下: 進捗バー(高さ10px、溝は`paper-track`+`paper-track-border`枠、塗りは`sakura`、`role="progressbar"`)
2. **達成メッセージ**(全件チェック済みのときだけ表示。`sakura-soft`背景、`radius-md`)
   - チェックマークの丸バッジ+「準備完了!忘れ物ゼロです」(`sakura-ink`)
3. **ツールバー行**(カードの外。上`space-6`・下`space-3`)
   - 左: 件数表示(`text-body-sm` / `ink-sub`): 「全8件・残り5件」。0件なら「まだ登録がありません」
   - 右: 「完了済みを隠す/表示」(完了が1件以上のときのみ)と「並べ替え」(2件以上のときのみ、段違い3本線アイコン付き)
   - 手動並べ替えモード中は、右側を「並べ替えを終える」1つだけにする
4. **リストカード**(`paper-surface`背景、`paper-border`枠線、`radius-lg`、`overflow-hidden`)
   - 0件かつ追加フォーム未展開の場合: `EmptyPacking`ブロック(枠線は破線)
   - 1件以上の場合: `PackingRow`を縦積み。行間は`paper-divider`の1px区切り線(先頭行には引かない)
   - 末尾に**インライン追加行**(`AddForm`)を置く
5. **非表示件数の注記**(「完了済みを隠す」がONのときだけ、カードの下に中央寄せで「完了済みn件を非表示中」)
6. **追従ボタン**(末尾の追加行が画面外にある間だけ表示。`fixed`右下、白地+`sakura-border`枠+`sakura-ink`文字、高さ50px、角丸`radius-full`)
7. **取り消しトースト**(削除直後の5秒間だけ表示。`ink`背景、`radius-md`、右端に「元に戻す」(`sakura-undo`))

## コンポーネント構造

```
<PackingTab>
  <PackingProgressCard total checkedCount />
  {allDone && <PackingAllDoneBanner />}
  <PackingToolbar count checkedCount showDone onToggleShowDone
                  onOpenSortSheet manualSortMode onExitManualSort />
  <ListCard>
    {isEmpty
      ? <EmptyPacking onStartAdd onAddFromTemplate />
      : items.map(item => (
          manualSortMode
            ? <PackingRowSortMode item isDragging registerRow onHandlePointerDown />
            : <PackingRow item flash onToggleCheck onOpenMenu />
        ))}
    {!manualSortMode && <PackingAddForm open value error duplicate ... />}
  </ListCard>
  {hiddenCount > 0 && <HiddenNote />}
  {fabVisible && <FollowFab label="持ち物を追加" />}
  {toast && <UndoToast onUndo />}
  {sortSheetOpen && <SortSheet current onPick />}
  {menuTarget && <RowActionSheet onSave onDelete />}
</PackingTab>
```

`SortSheet` / `RowActionSheet` / `UndoToast` / `FollowFab` / `ListCheckbox` / `BottomSheet` は
`src/components/list-ui/` に置く共有部品で、やることタブ(S3b)と共用する。

### PackingRow(1行)

横並び、行高さ68px、左右余白`space-4`:

1. チェックボックス(26px角丸。チェック済みは`sakura`塗り+白いチェックマーク、未チェックは白地+`ink-faint`の2px枠)。44×44pxのタップ領域の中に置く
2. ラベル(`text-body`、flex-grow、最大2行でクランプ)
   - `is_checked=true`のとき: 打ち消し線+`ink-done`
   - `is_checked=false`のとき: `ink`
3. 「済」バッジ(`is_checked=true`のときのみ、`ink-faint`)
4. 「…」ボタン(44×44pxタップ領域、`aria-label="<名前>の編集・削除"`)

**行の左側(チェックボックス〜ラベル〜「済」)全体が1つのトグルボタン**で、タップすると`is_checked`が切り替わる。
「…」はその隣に独立したボタンとして置く(ボタンの入れ子を避けるため)。

項目を追加した直後の行は`paper-flash`のハイライトを1.2秒かけてフェードさせ、どれが増えたかを示す。

### RowActionSheet(行メニューシート)

「…」から開くボトムシート。名前の編集欄+「保存する」、その下に「削除する」を置く。

- 旧UIの行内編集(✏️)・行内削除(🗑)を置き換える。行タップを完了トグルに割り当てたため、編集・削除はシートに集約する
- 「削除する」は1段階の確認(「「<名前>」を削除します。よろしいですか?」+「削除する」/「キャンセル」)を挟んでから確定する
- 削除を確定すると取り消しトーストを出す

### 並べ替えシート(SortSheet)

「並べ替え」から開くボトムシート。4択から1つ選ぶ:

| 選択肢 | 挙動 |
|---|---|
| 登録順 | `sort_order`昇順(既定) |
| 未完了を上に | 未完了を先頭へ寄せる。同じ状態の中では`sort_order`順を保つ |
| 完了済みを上に | 完了済みを先頭へ寄せる。同じ状態の中では`sort_order`順を保つ |
| 手動で並べ替え | 手動並べ替えモードに入る(下記`PackingRowSortMode`) |

選択値はしおり×タブ単位でlocalStorageに保存し、次回開いたときに復元する(`src/lib/list-sort-mode.ts`)。
DBスキーマは変更しない。「手動で並べ替え」を選ぶと、隠れた行を巻き込んで並べ替えないよう「完了済みを隠す」を強制的にOFFに戻す。

### PackingRowSortMode(手動並べ替えモード、1行)

1. ラベル(タップ操作不可、表示のみ、`ink`)
2. 行右端にドラッグハンドル(44×44pxタップ領域、`aria-label="<名前>をドラッグして並べ替え"`)

ハンドルを約300ms長押し→そのままドラッグすると並べ替えできる。ドラッグ中の行は影+半透明で強調し、他の行はドラッグ位置に応じてリアルタイムに並び直ることで挿入位置がわかるようにする。並べ替えモード中の行は`touch-action: none`にし、縦スクロールとの誤操作競合を防ぐ。指を離した時点の並びを`sort_order`として保存する。

チェックボックス・「…」・インライン追加行は手動並べ替えモード中は非表示にする(誤操作防止)。

### EmptyPacking(空状態)

破線枠(`paper-dashed`)のカード:

- 見出し(`ink-strong`、太字): 「持ち物はまだありません」
- 説明(`ink-sub`): 「忘れ物を防ぐために、必要なものを登録しましょう」
- 主ボタン(`sakura`背景、`radius-btn`、高さ52px): 「＋ 最初の持ち物を追加」→ インライン追加フォームを開く
- 副導線(`sakura-ink`のテキストボタン): 「テンプレから追加」
  - タップすると、しおりの`trip_type`に対応するテンプレート項目一式を`sort_order`0番から追加する

### AddForm(インライン追加)

リストカードの末尾に置く。画面下に固定していた旧フォームは廃止する。

**未展開時**: 「＋ 持ち物を追加」の行(高さ60px、`sakura-ink`の太字、上境界`paper-divider`)

**展開時**(`sakura-tint`背景):

- テキスト入力: プレースホルダー「例:モバイルバッテリー」、`sakura-field`の1.5px枠、文字数上限30文字
- 「キャンセル」+「登録する」ボタン(横並び)
- 入力を`trim()`した結果が空の場合は追加せず「持ち物の名前を入れてください」(`color-error`)を表示する
- 同名の持ち物が既にある場合は「同じ名前の持ち物がすでにあります」(`sakura-ink`)を出す。**警告のみで登録は妨げない**(同じ物を複数持つ場合があるため)
- ヒント(`ink-muted`): 「Enterで登録　続けて入力できます」
- Enterで登録、Escapeで閉じる
- 追加成功時: 末尾に追加し、入力欄を空にしてフォームは開いたままにする(連続入力しやすくするため)

## 状態

| 状態 | 表示 |
|------|------|
| ローディング | 準備状況カードとリスト行3本を`paper-track`のスケルトンで表示。読み込み後と同じ余白・行高にしてズレを抑える |
| 空(初回・テンプレ投入前) | 通常は自動投入が即時実行されるため一瞬で「一覧あり」に遷移する。投入処理自体が失敗した場合のみ次の「空(全削除後)」と同じ表示にフォールバックする |
| 空(全削除後、テンプレ投入済みフラグはtrueだが0件) | `EmptyPacking`ブロックを表示。準備状況カードは「登録0件」・進捗0%で表示し続ける |
| 一覧あり(通常モード) | `PackingRow`を選択中の並び順モードで表示 |
| 全件チェック済み | 準備状況カードの下に達成メッセージを出す |
| 完了済みを隠している | 未完了の行だけを表示し、カードの下に「完了済みn件を非表示中」を出す |
| 手動並べ替えモード | ツールバー右が「並べ替えを終える」だけになる。全行が`PackingRowSortMode`表示になり、インライン追加行は隠す |
| 行メニューを開いている | ボトムシート(名前編集+削除)を表示。背面はスクロールしない |
| 削除直後(5秒間) | 画面下に取り消しトーストを表示 |
| 追加フォーム入力エラー | 入力欄下に「持ち物の名前を入れてください」(`color-error`) |
| 追加フォームの重複警告 | 入力欄下に「同じ名前の持ち物がすでにあります」(`sakura-ink`)。登録は妨げない |
| オフライン | データはIndexedDBのローカル参照のみのため通信不要。オフライン専用の表示分岐は無し |

## タップ時の挙動

| 要素 | 挙動 |
|------|------|
| 行の左側(チェックボックス〜ラベル) | `is_checked`をトグルしIndexedDBへ即時保存(保存ボタン不要) |
| 行の「…」ボタン | 行メニューシート(名前編集+削除)を開く |
| 行メニューの「保存する」 | 入力値(空でなければ)でラベルを更新しシートを閉じる。空の場合は保存せず「持ち物の名前を入れてください」を表示 |
| 行メニューの「削除する」 | 削除確認に進む |
| 削除確認の「削除する」 | 項目を削除し、以降の項目の`sort_order`を詰め、取り消しトーストを出す |
| トーストの「元に戻す」 | 削除した名前で項目を作り直す。**元の位置ではなく末尾に戻る**(guest-storeに任意位置への挿入APIが無いための仮置き) |
| ツールバーの「並べ替え」 | 並べ替えシートを開く |
| ツールバーの「完了済みを隠す/表示」 | 完了済みの行の表示/非表示を切り替える(保存はしない。タブを開き直すと表示に戻る) |
| 並べ替えシートの選択肢 | 並び順モードを切り替え、localStorageに保存してシートを閉じる |
| 「並べ替えを終える」 | 「登録順」に戻る |
| ドラッグハンドルの長押し→ドラッグ | 約300ms長押し後、指の移動に追従して挿入位置を更新する。離した時点の並びで全項目の`sort_order`を振り直す |
| EmptyPackingの「＋ 最初の持ち物を追加」 | インライン追加フォームを開く |
| EmptyPackingの「テンプレから追加」 | `trip_type`対応テンプレート項目一式を追加する |
| 「＋ 持ち物を追加」行 / 追従ボタン | インライン追加フォームを開く |
| 追加フォームの「登録する」/ Enter | 入力値をバリデーションし、問題なければ末尾に追加してフォームを開いたままにする |

## 遠征当日の利用シーン確認

- 当日はチェック操作が中心。チェックボックスは44×44px確保し、片手の親指操作でも押しやすい位置(行の左端固定)にする
- 並べ替え・編集・削除は事前準備段階での操作を想定し、当日はチェックのみで完結できる構造にした
- 通信不要(IndexedDBのみ)で全操作が成立する
