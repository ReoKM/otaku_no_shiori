# S3b2 予算(やることタブ内「予算」セクション)

対応機能: 予算管理(オーナー草案。F番号未採番・`docs/01_service_spec.md`未反映)
参照: `docs/design/screens/S3b_TODO.md`(同一タブ) / `docs/design/screens/S3c_旅程スポット.md`(セグメント切替の前例) / `docs/design/tokens.md`
ルーティング: `/shiori/[id]/todo`(タブシェルは`S3_しおり詳細.md`参照)。セクション選択はURLに持たせずタブ内状態で保持する

> このファイルはUI設計の確定案。`docs/01_service_spec.md`への機能追記はPM経由でオーナー承認後に行う(本ファイルは仕様の正ではない)。

## 前提: 配置の決定

- 予算は**独立タブを作らず、やることタブ(S3b)内のセグメント切替**に入れる。セグメントは「やること / 予算」の2分割。
- 理由:
  1. タブ5個は375px幅でラベル間の余白が確保できない(下記「タブ5個の不採用根拠」)
  2. 予算は**準備期のタスク**であり、F3テンプレートの「遠征資金の準備」と同じ文脈にある。やることタブと利用フェーズが一致する
  3. スポット(F5)を旅程タブ内セグメントに入れた2026-07-11の前例と同じ構造にでき、新しいUIパターンを増やさない
- デフォルト選択: 「やること」(タブを開いたときの初期表示)。予算セクションは明示的に切り替えたときだけ出す
- 新規の色トークン・新規UIパターンは追加しない。`list-ui/`(BottomSheet / RowActionSheet / UndoToast / FollowFab)と紙テイストのカード・破線空状態を再利用する

### タブ5個の不採用根拠(375px実測ベース)

現行タブバー(`src/components/shiori-detail/TabBar.tsx`)は`grid-cols-4`・横パディング0・高さ48px・`text-[15px] tracking-[0.02em]`。

| 項目 | 4タブ(現行) | 5タブ |
|---|---|---|
| 1タブの幅(375px) | 93.75px | 75.0px |
| 最長ラベル「やること」の実幅(15px全角4字+字間0.3px×4) | 61.2px | 61.2px |
| ラベル左右の余白(片側) | 16.3px | 6.9px |
| 隣接ラベル間の距離 | 32.6px | 13.8px |
| タップ領域(幅×高さ) | 93.75×48px(基準44px以上) | 75×48px(基準44px以上) |

- **タップ領域44pxは5タブでも満たす**(75px)。破綻するのはタップではなく**可読性**。
- 隣接ラベル間13.8pxは文字高15pxを下回り、「やること|旅程|記録|予算」が1本の文字列として読める状態になる。トークンの最小間隔`space-3`(12px)を片側に取ると 61.2+24=85.2px > 75px で成立しない。
- 5タブに収めるにはラベルを**3文字以内**((75−24)÷15.3=3.3字)に制限する必要があり、既存の「やること」を改名しなければならない。既存ラベルを崩してまで得る配置ではない。
- 320px幅端末(iPhone SE系)では1タブ64.0pxとなり、「やること」61.2pxに対し片側余白1.4pxで即破綻する。
- 端末のテキスト拡大(iOS/Androidの大きい文字)は日本語ラベルを等倍で押し広げるため、5タブは拡大率100%でも余白が不足し、拡大時は折り返し・見切れが発生する。

結論: **タブは4個のまま据え置く。**

## レイアウト(上から順、やることタブのコンテンツ領域)

1. **セグメント切替**(「やること」/「予算」の2分割)
   - タブバー直下に密着。高さ44px以上、左右余白`space-4`、上下`space-3`
   - 選択中: `sakura-ink`の太字+下辺2.5pxの`sakura`インクバー。未選択: `ink-strong`の中太(S3cと同一)
2. **予算サマリーカード**(`paper-surface`背景、`paper-border`枠線、`radius-lg`、内側`px-4 py-3.5`)
   - 1行目 左: 「予算総額」(`text-label` / `ink-label`)/ 右: 「変更」ボタン(白地+`sakura-border`枠+`sakura-ink`文字、高さ44px、`radius-md`)
   - 2行目: 総額(`text-title-compact` / `ink`、`tabular-nums`): 「¥50,000」
   - 3行目: 進捗バー(高さ10px、溝`paper-track`+`paper-track-border`枠、塗り`sakura`、`radius-full`、`role="progressbar"`)。割合 = 割り当て済み ÷ 総額(100%超は100%で止める)
   - 4行目: 左「割り当て済み ¥32,800」(`text-body-sm` / `ink-sub`)/ 右「残り ¥17,200」(`text-body-sm`。残りが1円以上なら`sakura-ink`、0なら`ink-sub`)
   - 超過時の4行目右: 「¥3,200 超過」(`sakura-ink`)。入力エラーではないため`color-error`は使わない(`tokens.md` 1-4の規約)
3. **ツールバー行**(カードの外。上`space-6`・下`space-3`、`text-body-sm` / `ink-sub`)
   - 左のみ: 「全n件」。0件なら「まだ費目がありません」。並べ替え・絞り込みは持たない
4. **費目リストカード**(`paper-surface`背景、`paper-border`枠線、`radius-lg`、`overflow-hidden`)
   - 0件かつ追加フォーム未展開: `EmptyBudget`ブロック(枠線は破線`paper-dashed`)
   - 1件以上: `BudgetRow`を登録順で縦積み。行間は`paper-divider`の1px区切り線(先頭行には引かない)
   - 末尾に**インライン追加行**(`AddBudgetForm`)
5. **メモカード**(`paper-surface`背景、`paper-border`枠線、`radius-lg`、内側`space-4`)
   - 見出し「メモ」(`text-label` / `ink-label`)、下に本文(`text-body` / `ink`、最大200文字)
   - 未入力時は本文位置にプレースホルダー(`ink-muted`)。カードをタップすると編集状態になる
6. **追従ボタン**(末尾の追加行が画面外にある間だけ。ラベル「費目を追加」。`FollowFab`を再利用)
7. **取り消しトースト**(費目削除直後の5秒間だけ。`UndoToast`を再利用)

左右余白は`space-6`(24px)でやること/持ち物と揃える。広告枠(F9)は置かない。

## コンポーネント構造

```
<TodoTab>
  <SegmentedControl active={section} onChange={setSection}>
    <Segment id="todo"   label="やること" />
    <Segment id="budget" label="予算" />
  </SegmentedControl>
  {section === "todo"   && <TodoSection />}     // S3b_TODO.md の既存内容をそのまま入れる
  {section === "budget" && <BudgetSection />}
</TodoTab>

<BudgetSection>
  <BudgetSummaryCard total allocated remaining onOpenTotalSheet />
  <Toolbar count />
  <ListCard>
    {items.length === 0
      ? <EmptyBudget onStartAdd />
      : items.map(item => <BudgetRow item flash onOpenMenu />)}
    <AddBudgetForm open onOpen onClose onAdd />
  </ListCard>
  <BudgetMemoCard value editing onStartEdit onSave onCancel />
  {fabVisible && <FollowFab label="費目を追加" />}
  {toast && <UndoToast onUndo />}
  {totalSheetOpen && <BudgetTotalSheet current onSave onClose />}
  {menuTarget && <BudgetActionSheet item onSave onDelete />}
</BudgetSection>
```

`BottomSheet` / `UndoToast` / `FollowFab` は`src/components/list-ui/`の共有部品。
`BudgetTotalSheet` / `BudgetActionSheet` は`BottomSheet`の上に組む(`RowActionSheet`は名前1項目専用のため、金額欄を持つ本セクションでは`TodoActionSheet`と同じ考え方で専用シートにする)。

### BudgetRow(1行)

横並び、行高さ56px、左右余白`space-4`。

1. 費目名(`text-body` / `ink`、1行`truncate`)
2. 金額(右寄せ、`text-body` / `ink`、`tabular-nums`): 「¥12,800」
3. 「…」ボタン(44×44pxタップ領域、`aria-label="<費目名>の編集・削除"`)

行の左側(費目名〜金額)全体が1つのボタンで、タップすると行メニューシートを開く(チェック状態を持たないため、持ち物・やることのようなトグルはしない)。
追加直後の行は`paper-flash`で1.2秒ハイライトする。

### BudgetSummaryCard

- 総額未設定(`null`)のときは**破線枠**(`paper-dashed`)のカードに置き換える(下記`EmptyBudgetTotal`)
- 総額0円は「設定済み・0円」として扱い、破線にはしない

#### EmptyBudgetTotal(総額未設定)

- 見出し(`text-body` / `ink-strong`): 「予算はまだ決めていません」
- 説明(`text-body-sm` / `ink-muted`): 「総額を決めると、費目ごとの割り当てと残りが見えます」
- 主ボタン(`sakura`背景・白文字、高さ44px、`radius-btn`): 「予算総額を決める」

### BudgetTotalSheet(総額入力シート)

`BottomSheet`。上端`radius-lg`、背面はスクロールしない。

1. 見出し「予算総額」(`text-label` / `ink-label`)
2. 金額入力欄(高さ44px以上、`radius-md`、枠`sakura-field`、`inputMode="numeric"`、左に「¥」を固定表示)
3. ヒント(`text-caption` / `ink-muted`): 「あとから変更できます」
4. 「保存する」(`sakura`背景・白文字、高さ44px、`radius-btn`)
5. 総額設定済みのときのみ「予算をクリアする」(`text-body-sm` / `color-error`)

### AddBudgetForm(インライン追加)

リストカード末尾。

**未展開時**: 「＋ 費目を追加」の行(高さ60px、`sakura-ink`)

**展開時**(背景`sakura-tint`):

1. 費目名の入力欄(プレースホルダー「例:交通費」、最大20文字)
2. 金額の入力欄(プレースホルダー「0」、左に「¥」固定表示、`inputMode="numeric"`)
3. 「キャンセル」/「登録する」
4. ヒント(`text-caption` / `ink-muted`): 「金額はあとから変更できます」

Enterで登録(フォームは開いたまま)、Escapeで閉じる。登録後は費目名の欄にフォーカスを戻す。

### BudgetActionSheet(行メニューシート)

`BottomSheet`。費目名の編集欄+金額の編集欄+「保存する」、その下に「削除する」。
「削除する」は1段階の確認を挟み、確定後に取り消しトーストを出す(やることタブと同じ)。

### EmptyBudget(費目0件の空状態)

破線枠のカード(`paper-dashed`)。

- 見出し: 「費目はまだありません」
- 説明: 「交通費・宿・グッズなど、使い道ごとに金額を分けましょう」
- 主ボタン: 「＋ 最初の費目を追加」

### BudgetMemoCard

- 表示状態: 本文(最大200文字、改行保持)。未入力時はプレースホルダー
- 編集状態: 複数行入力欄(`radius-md`、枠`sakura-field`、背景`sakura-tint`)+右下に文字数カウンタ(`text-caption` / `ink-muted`、上限超過で`color-error`)+「キャンセル」/「保存する」

## 金額の表示・入力規則

| 項目 | 規則 |
|---|---|
| 通貨記号 | 半角「¥」を数値の前に置く(「円」は使わない。桁が伸びても幅が増えないため) |
| 桁区切り | 半角カンマの3桁区切り。例: `¥12,800` |
| 端数 | 円単位の整数のみ。小数点は入力できない(丸め処理を持たないため、そもそも入れさせない) |
| ゼロ | 空欄にせず「¥0」と表示する |
| マイナス | 入力不可。残額のマイナスは負数表示ではなく「¥3,200 超過」と表記する |
| 省略表記 | 「5万」等の万表記はしない(誤読防止)。桁が伸びても等幅数字(`tabular-nums`)で表示する |
| 入力欄 | `inputMode="numeric"`。全角数字は半角へ自動変換し、数字以外の文字は破棄する。表示中もカンマは入れない(キャレット移動の破綻を避ける) |
| 上限 | 総額・費目とも 9,999,999(7桁)。超えた入力は受け付けずエラー文言を出す |
| 費目件数 | 上限20件(仮置き) |

## 状態

| 状態 | 表示 |
|------|------|
| ローディング(IndexedDB読込中) | サマリーカードと費目行3本を`paper-track`のスケルトンで表示。読込後と同じ余白・行高にする |
| 初期(総額未設定・費目0件) | `EmptyBudgetTotal`(破線カード)のみ。費目リスト・メモカード・追従ボタンは表示しない(先に総額を決める導線に集中させる) |
| 総額設定済み・費目0件 | サマリーカード(割り当て済み¥0・残り=総額・バー0%)+`EmptyBudget`+メモカード |
| 一覧あり | `BudgetRow`を登録順で表示。サマリーは合計・残り・バーを即時反映 |
| 総額入力シート表示中 | `BudgetTotalSheet`を表示。背面はスクロールしない |
| 費目追加フォーム展開中 | リストカード末尾に`AddBudgetForm`をインライン表示 |
| 行メニューを開いている | `BudgetActionSheet`(費目名+金額+削除)を表示 |
| 削除直後(5秒間) | 画面下に取り消しトーストを表示 |
| エラー(費目名未入力) | 費目名欄の下に「費目名を入れてください」(`color-error`)。枠線`color-error-border`・背景`color-error-bg` |
| エラー(金額未入力・数字以外) | 金額欄の下に「金額を数字で入れてください」(`color-error`) |
| エラー(桁超過) | 金額欄の下に「金額は9,999,999円までです」(`color-error`) |
| エラー(費目件数上限) | 追加行の代わりに「費目は20件までです」(`text-caption` / `ink-muted`)を表示し、追加フォームを開けなくする |
| 注意(割り当て超過) | サマリーの残り表示を「¥n 超過」(`sakura-ink`)に変える。保存は妨げない。バーは100%で止める |
| 注意(メモ文字数超過) | カウンタを`color-error`にし「保存する」を無効化 |
| オフライン | 全操作がIndexedDBのみで完結し通信不要。オフライン専用の表示分岐は無し |

## タップ時の挙動

| 要素 | 挙動 |
|------|------|
| セグメント「やること」/「予算」 | 表示セクションを切り替える(読込済みのローカルデータを出し分けるのみ。通信しない) |
| 「予算総額を決める」/「変更」 | `BudgetTotalSheet`を開く |
| 総額シートの「保存する」 | 数値を検証し、問題なければ総額を保存してシートを閉じる。エラー時は閉じない |
| 総額シートの「予算をクリアする」 | 1段階の確認後、総額を未設定に戻す。**費目とメモは消さない**(残す) |
| 「＋ 最初の費目を追加」/「＋ 費目を追加」/ 追従ボタン | `AddBudgetForm`を展開し費目名にフォーカスする |
| 追加フォームの「登録する」/ Enter | 検証後、リスト末尾に追加してフォームは開いたままにする。追加行を`paper-flash`でハイライト |
| 追加フォームの「キャンセル」/ Escape | フォームを閉じ、何も追加しない |
| 費目行の左側(費目名〜金額) | `BudgetActionSheet`を開く |
| 費目行の「…」ボタン | 同上(`BudgetActionSheet`を開く) |
| 行メニューの「保存する」 | 費目名・金額を検証して更新しシートを閉じる |
| 行メニューの「削除する」 | 削除確認に進む |
| 削除確認の「削除する」 | 費目を削除し、取り消しトーストを出す |
| トーストの「元に戻す」 | 削除した費目名・金額で作り直す。**元の位置ではなく末尾に戻る**(やることタブと同じ制約) |
| メモカード本文 | 編集状態にし、入力欄にフォーカスする |
| メモの「保存する」 | 内容を保存し表示状態へ戻す |
| メモの「キャンセル」 | 変更を破棄し表示状態へ戻す |

## 遠征当日の利用シーン確認

- 予算は**準備期に決めて当日に参照する**情報。当日に必要なのは「残りいくら使えるか」の1点なので、セクションを開いた最初の画面(サマリーカード)で総額・割り当て済み・残りが一目で読めるようにした。スクロールも操作も不要
- 当日の中心である持ち物・旅程タブには一切の追加要素を置かないため、当日の導線は現状のまま変わらない
- 全操作がIndexedDB完結で通信不要。電波の弱い会場でも表示・編集できる(F10のオフライン対象に加える必要がある)

## 不明点・仮置き

- 予算機能は`docs/01_service_spec.md`に未記載。F番号の採番・MVP/Phase2の振り分けはPM経由でオーナー判断が必要
- 費目プリセット(交通/宿/グッズ/食事/予備費)の自動投入は**本仕様では行わない**(「手入力が最小形」という前提に従った)。持ち物・やることと同じテンプレ投入にするかは要判断
- 実支出の記録(予定額に対する実績)は本仕様の対象外。最小形の指定どおり「割り当て」のみ
