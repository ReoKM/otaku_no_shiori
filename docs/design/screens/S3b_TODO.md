# S3b TODO(TODOタブ)

対応機能: F3 / 参照: `docs/01_service_spec.md`
ルーティング: `/shiori/[id]/todo`(タブシェルは`S3_しおり詳細.md`参照)
デザイントークン: `docs/design/tokens.md`

## 前提: テンプレ自動投入のタイミング(持ち物タブと同パターン、アーキテクト確定仕様)

- TODOタブを**初めて開いた時点**でデータが0件なら、`docs/01_service_spec.md`のF3テンプレート(チケット申込/当落確認/チケット発券/ホテル予約/交通手配/遠征資金の準備 など)を自動投入する。テンプレートは遠征タイプに依らず共通1種とする(F3の仕様に遠征タイプ別テンプレの記載が無いため)
- ユーザーが全項目を削除して0件に戻った場合は自動再投入しない。空状態に「テンプレから追加」ボタンを表示し、手動操作でのみ再投入する
- 実装上の注意(frontend-dev向け): `S3a_持ち物.md`と同様に、しおりごとの**テンプレ投入済みフラグ**(例: `todoTemplateSeeded: boolean`)で「初回」と「全削除後」を区別すること。0件かどうかだけで自動投入を判定しない

## レイアウト(上から順、タブシェル内のコンテンツ領域)

1. **ツールバー行**(左右余白`space-4`、高さ44px以上)
   - 左: 件数表示(`text-body-sm` / `color-text-secondary`): 「6件」
   - 右: 「並べ替え」テキストボタン(項目が2件以上の時のみ表示。並べ替えモード中は「完了」に文言変化)
2. **リストエリア**(縦スクロール、項目間`color-border-default`の1px区切り線)
   - 0件の場合: `EmptyTodo`ブロック
   - 1件以上の場合: `TodoRow`を並び順に縦積み(下記ソート規則参照)
3. **手動追加フォーム**(`sticky bottom-0`、背景`color-bg-surface`、上境界`color-border-default`、内側パディング`space-4`、2行構成)
   - 1行目: ラベルのテキスト入力(プレースホルダー「例: チケット当落確認」)
   - 2行目: 期限日の日付入力(任意、プレースホルダー「期限日(任意)」)+「追加」ボタン(同じ行の右側)

## ソート規則(F3「期限が近い順に表示」)

- **未完了(`is_done=false`)の項目を上部、完了済み(`is_done=true`)の項目を末尾にまとめる**(仮置き。F3仕様は「期限が近い順に表示」のみだが、完了済みが上部に残り続けると直近の未完了TODOが埋もれて実用性を損なうため。レビュー指摘を受けて採用)
- 未完了・完了済みの各グループ内では、`due_date`が設定されている項目を**日付が近い順(昇順)**に表示する
- `due_date`が未設定の項目は**各グループの末尾**にまとめる(未設定同士の順序は`sort_order`または追加順)
- 完了済み項目は見た目も完了表示(打ち消し線+`color-text-muted`)にする
- 過去日(期限切れ・未完了)の扱いについて仕様に記載が無いため、期限切れでも「近い順」の並び(昇順)にそのまま従う。特別な強調は行わない(仮置き。詳細は完了報告参照)

## コンポーネント構造

```
<TodoTab>
  <Toolbar count={items.length} sortMode onToggleSort />
  <List>
    {items.length === 0
      ? <EmptyTodo onAddFromTemplate />
      : sortedItems.map(item => (
          sortMode
            ? <TodoRowSortMode item={item} isDragging registerRow onHandlePointerDown />
            : <TodoRow item={item} onToggleDone onEdit onDelete />
        ))}
  </List>
  <AddForm onAdd={(label, dueDate) => ...} />
</TodoTab>
```

### TodoRow(通常モード、1行)

横並び、行高さ56px以上、左右余白`space-4`。当日期限の行は背景`color-due-today-bg`+左端4pxの`color-due-today-border`を追加する(下記「期限当日の強調」参照)。

1. チェックボックス(44×44pxタップ領域)。タップで`is_done`をトグル
2. テキスト情報(縦積み、flex-grow)
   - ラベル(`text-body`)。`is_done=true`のとき打ち消し線+`color-text-muted`
   - 期限日(`text-body-sm`、設定時のみ表示): 「8/15(土)」形式(月/日+曜日、年は表示しない)。当日の場合は`color-due-today-text`で表示し、末尾に「(今日)」を付与
   - 期限日が未設定の場合、期限日行自体を表示しない
3. 編集ボタン(鉛筆アイコン、44×44px)
4. 削除ボタン(ゴミ箱アイコン、44×44px)

### TodoRow(編集中)

編集ボタン押下後、ラベルと期限日がそれぞれテキスト入力・日付入力に置き換わり、右側アイコンが「保存(✓)」「キャンセル(×)」に変わる。期限日入力には「期限を削除」リンク(`text-caption`)を添え、タップすると期限日をクリアできる。

### TodoRow(削除確認中)

`S3a_持ち物.md`のPackingRowと同じインライン確認パターン(「本当に削除しますか？」+「削除」+「キャンセル」)。

### TodoRowSortMode(並べ替えモード、1行)

`S3a_持ち物.md`のPackingRowSortModeと同じ構造(ラベル+行右端のドラッグハンドル≡)。行右端のハンドルを約300ms長押し→ドラッグで並べ替える(上下矢印ボタンは廃止。オーナーフィードバック反映)。**並べ替えモードは手動での順序上書きに使うが、通常モードの表示は常に「ソート規則」に従うため、並べ替えモードで変更した順序は同じ期限日/期限なし同士のグループ内の並び(タイブレーク)にのみ影響する**(異なる期限日を持つ項目同士の順序は`sort_order`では変えられない)。

グループ境界での誤解(「ドラッグしても他のグループへ移動できない」ように見える)を防ぐため、並べ替えモードでは次の制御を行う:

- ドラッグは**同じ期限日(または期限なし)グループ内での移動のみ有効**にする(グループ境界を越えて指を動かしても、挿入位置はグループの先頭/末尾でクランプされる)
- 並べ替えモード中の行にも期限日を小さく表示し、どこがグループ境界かわかるようにする
- ドラッグ中の行は影+半透明で強調し、他の行はドラッグ位置に応じてリアルタイムに並び直る。並べ替えモード中の行は`touch-action: none`にし、縦スクロールとの誤操作競合を防ぐ

### EmptyTodo(空状態)

- 説明文(`text-body` / `color-text-secondary`): 「まだTODOがありません」
- ボタン(`color-primary`背景、`radius-md`): 「テンプレから追加」
  - タップするとF3テンプレート項目一式(期限日は全て未設定)を追加する

### AddForm(手動追加フォーム)

- ラベル入力: プレースホルダー「例: チケット当落確認」、文字数上限30文字(仮置き、`S3a_持ち物.md`と揃えた)
- 期限日入力: 任意。日付ピッカー(`<input type="date">`相当)。未入力のままでもよい。日付を選択済みの場合は入力欄の右に「×」クリアボタン(44×44pxタップ領域)を表示し、タップで未設定に戻せる(モバイルブラウザの標準UIでは一度選んだ日付をクリアしにくいため。編集モードのクリア手段と同じ扱い)
- 「追加」ボタン: ラベルを`trim()`(前後の半角・全角スペース除去)した結果が空の場合はタップしても追加せず「TODOの名前を入れてください」(`color-error`)を表示する。保存時もトリム後の文字列を保存する(編集保存時も同じ扱い。`S3a_持ち物.md`と同基準)
- 追加成功時: 新しい項目を`is_done=false`で追加し、ソート規則に従って適切な位置に挿入表示する。フォームは空に戻りラベル入力にフォーカスを維持する

## 期限当日の強調表示

- 対象: `due_date`が本日の日付と一致し、かつ`is_done=false`の項目(完了済みは強調しない)
- 表示: 行全体の背景を`color-due-today-bg`、左端4pxの縦線を`color-due-today-border`、期限日テキストを`color-due-today-text`+「(今日)」を付与
- プッシュ通知等は行わない(F3仕様どおりMVP非対応)

## 状態

| 状態 | 表示 |
|------|------|
| ローディング | リストエリアに`color-bg-disabled`のスケルトン行を3本表示 |
| 空(初回・テンプレ投入前) | 通常は自動投入が即時実行され一瞬で「一覧あり」に遷移する。投入失敗時のみ次の「空(全削除後)」と同じ表示にフォールバックする |
| 空(全削除後、テンプレ投入済みフラグはtrueだが0件) | `EmptyTodo`ブロックを表示。手動追加フォームは通常どおり表示し続ける |
| 一覧あり(通常モード) | `TodoRow`をソート規則(期限が近い順、期限なしは末尾)で表示。当日期限の行は強調表示 |
| 並べ替えモード | ツールバー右ボタンが「完了」に変化。全行が`TodoRowSortMode`表示になる |
| 行編集中 | 該当行のみラベル・期限日が入力状態になる |
| 行削除確認中 | 該当行のみ確認UIになる |
| 追加フォーム入力エラー | ラベル入力欄下に「TODOの名前を入れてください」(`color-error`) |
| オフライン | データはIndexedDBのローカル参照のみのため通信不要。オフライン専用の表示分岐は無し |

## タップ時の挙動

| 要素 | 挙動 |
|------|------|
| チェックボックス | `is_done`をトグルしIndexedDBへ即時保存 |
| 編集(鉛筆)ボタン | その行を編集モードにする |
| 編集中の保存(✓) | ラベル(空でなければ)・期限日を更新し通常表示へ戻る。ラベルが空の場合は保存せずエラー表示 |
| 編集中の「期限を削除」 | 期限日入力をクリアする(保存はまだ確定しない、保存(✓)押下で確定) |
| 編集中のキャンセル(×) | 変更を破棄し通常表示へ戻る |
| 削除(ゴミ箱)ボタン | その行を削除確認状態にする |
| 削除確認中の「削除」 | 項目を削除する |
| 削除確認中の「キャンセル」 | 通常表示へ戻る |
| ツールバーの「並べ替え」 | 並べ替えモードへ切り替える |
| 並べ替えモードの「完了」 | 通常モードへ戻る |
| ドラッグハンドル(≡)の長押し→ドラッグ | 約300ms長押し後、指の移動に追従して同じ期限グループ内の挿入位置を更新する。離した時点の並びでタイブレーク順(`sort_order`)を更新する |
| EmptyTodoの「テンプレから追加」 | F3テンプレート項目一式(期限日未設定)を追加する |
| AddFormの「追加」 | ラベルをバリデーションし、問題なければソート規則に従う位置に新規項目を追加する |

## 遠征当日の利用シーン確認

- 当日は「当日期限の強調」を頼りに片手でチェックしていく想定。強調色(`color-due-today-*`)は一覧を流し見でも視認できるコントラストにする
- 並べ替え・編集・削除は事前準備段階での操作を想定
- 通信不要(IndexedDBのみ)で全操作が成立する

## 不明点・仮置き(完了報告にも記載)

- 手動追加項目の文字数上限30文字は仕様に数値記載が無いため仮置き(`S3a_持ち物.md`・`S2_しおり作成.md`と揃えた)
- 完了済み(`is_done=true`)項目の扱いは仕様に記載が無い。当初は「位置は変えず見た目のみ変更」としたが、完了済みが上部に残ると直近の未完了TODOが埋もれるというレビュー指摘を受け、「未完了を上部・完了済みを末尾にまとめる」に変更した(仮置き)
- 期限切れ(過去日・未完了)項目の特別な強調は仕様に記載が無いため、当日以外は強調しない扱いとした
- F3テンプレートは仕様上「遠征タイプ別」の記載が無いため、共通1種として扱った(F2は遠征タイプ別テンプレのため差異がある点に注意)
