# S3b TODO(TODOタブ)

対応機能: F3 / 参照: `docs/01_service_spec.md`
ルーティング: `/shiori/[id]/todo`(タブシェルは`S3_しおり詳細.md`参照)
デザイントークン: `docs/design/tokens.md`

## 前提: テンプレ自動投入のタイミング(持ち物タブと同パターン、アーキテクト確定仕様)

- TODOタブを**初めて開いた時点**でデータが0件なら、`docs/01_service_spec.md`のF3テンプレート(チケット申込/当落確認/チケット発券/ホテル予約/交通手配/遠征資金の準備 など)を自動投入する。テンプレートは遠征タイプに依らず共通1種とする(F3の仕様に遠征タイプ別テンプレの記載が無いため)
- ユーザーが全項目を削除して0件に戻った場合は自動再投入しない。空状態に「テンプレから追加」ボタンを表示し、手動操作でのみ再投入する
- 実装上の注意(frontend-dev向け): `S3a_持ち物.md`と同様に、しおりごとの**テンプレ投入済みフラグ**(例: `todoTemplateSeeded: boolean`)で「初回」と「全削除後」を区別すること。0件かどうかだけで自動投入を判定しない

## レイアウト(上から順、タブシェル内のコンテンツ領域)

持ち物タブ(`S3a_持ち物.md`)と同じ構成。左右余白は`space-6`(24px)。

1. **進捗カード**(見出しは「やること」。それ以外は持ち物の準備状況カードと同じ)
2. **ツールバー行**(件数 / 「完了済みを隠す・表示」 / 「並べ替え」)
3. **リストカード**(`TodoRow`を縦積み、末尾にインライン追加行)
4. **非表示件数の注記**(「完了済みを隠す」がONのときだけ)
5. **追従ボタン**(末尾の追加行が画面外にある間だけ。ラベルは「やることを追加」)
6. **取り消しトースト**(削除直後の5秒間だけ)

達成メッセージ(全件完了時のバナー)は持ち物タブのみ。やることは「忘れ物ゼロ」に相当する
声かけ文言が無いため置かない。

## ソート規則(F3「期限が近い順に表示」)

並び順は**並べ替えシートで5択**から選ぶ。選択値はしおり単位でlocalStorageに保存する
(`src/lib/list-sort-mode.ts`)。

| 選択肢 | 挙動 |
|---|---|
| **期限が近い順(既定)** | 下記の規則。F3の要件を満たす並び |
| 登録順 | `sort_order`昇順 |
| 未完了を上に | 未完了を先頭へ寄せる。同じ状態の中では`sort_order`順を保つ |
| 完了済みを上に | 完了済みを先頭へ寄せる。同じ状態の中では`sort_order`順を保つ |
| 手動で並べ替え | 手動並べ替えモードに入る |

「期限が近い順」は持ち物タブには無いやること限定の選択肢。デザイン案の4択には含まれないが、
`docs/01_service_spec.md` のF3が「期限が近い順に表示」を求めているため既定の並びとして残す。

「期限が近い順」の並び:

- **未完了(`is_done=false`)の項目を上部、完了済み(`is_done=true`)の項目を末尾にまとめる**(完了済みが上部に残り続けると直近の未完了やることが埋もれて実用性を損なうため)
- 未完了・完了済みの各グループ内では、`due_date`が設定されている項目を**日付が近い順(昇順)**に表示する
- `due_date`が未設定の項目は**各グループの末尾**にまとめる(未設定同士の順序は`sort_order`順)
- 完了済み項目は見た目も完了表示(打ち消し線+`ink-done`)にする
- 過去日(期限切れ・未完了)も「近い順」の並び(昇順)にそのまま従う。特別な強調は行わない(仮置き)

## コンポーネント構造

```
<TodoTab>
  <TodoProgressCard total doneCount />
  <Toolbar count doneCount showDone onToggleShowDone
           onOpenSortSheet manualSortMode onExitManualSort />
  <ListCard>
    {isEmpty
      ? <EmptyTodo onStartAdd onAddFromTemplate />
      : todos.map(item => (
          manualSortMode
            ? <TodoRowSortMode item isDragging registerRow onHandlePointerDown />
            : <TodoRow item dueToday flash onToggleDone onOpenMenu />
        ))}
    {!manualSortMode && <AddForm open onOpen onClose onAdd />}
  </ListCard>
  {hiddenCount > 0 && <HiddenNote />}
  {fabVisible && <FollowFab label="やることを追加" />}
  {toast && <UndoToast onUndo />}
  {sortSheetOpen && <SortSheet modes={SORT_MODES_BY_TAB.todo} current onPick />}
  {menuTarget && <TodoActionSheet onSave onDelete />}
</TodoTab>
```

`SortSheet` / `UndoToast` / `FollowFab` / `ListCheckbox` / `BottomSheet` は
`src/components/list-ui/` の共有部品(持ち物タブと共用)。

### TodoRow(1行)

横並び、行高さ68px、左右余白`space-4`。持ち物の`PackingRow`に期限日の行を足した構造:

1. チェックボックス(26px角丸。44×44pxのタップ領域の中に置く)
2. 名前(`text-body`、最大2行でクランプ)
   - `is_done=true`のとき: 打ち消し線+`ink-done`
3. 期限(`due_date`があるときのみ、名前の下に「期限 7/25(土)」)
   - 完了済み: `ink-faint` / 期限当日: `color-due-today-text` + 「・今日」を付ける / それ以外: `ink-muted`
4. 「済」バッジ(`is_done=true`のときのみ)
5. 「…」ボタン(44×44pxタップ領域、`aria-label="<名前>の編集・削除"`)

**行の左側(チェックボックス〜名前・期限〜「済」)全体が1つのトグルボタン**で、タップすると`is_done`が切り替わる。

### TodoActionSheet(行メニューシート)

「…」から開くボトムシート。名前の編集欄+期限の日付入力(+「期限を消す」)+「保存する」、その下に「削除する」。

- 持ち物の`RowActionSheet`と同じ役割だが、やることは**期限も編集する**ため専用に持つ
- 「削除する」は1段階の確認を挟んでから確定し、確定後は取り消しトーストを出す

### TodoRowSortMode(手動並べ替えモード、1行)

1. 名前と期限(タップ操作不可、表示のみ)
2. 行右端にドラッグハンドル(44×44pxタップ領域、`aria-label="<名前>をドラッグして並べ替え"`)

ハンドルを約300ms長押し→ドラッグで並べ替える。ドラッグ中の行は影+半透明で強調する。

**「期限が近い順」のときだけ**、同じ期限グループ(完了状態+期限日の組み合わせ)内に移動を制限する。
表示順が期限で決まるモードでグループを越えて動かしても、離した瞬間に元の位置へ戻って見えてしまうため。
他のモードは表示順が期限に依存しないので制限しない。

### EmptyTodo(空状態)

破線枠のカード。持ち物の`EmptyPacking`と同じ構成:

- 見出し: 「やることはまだありません」
- 説明: 「チケット申込や宿の予約など、遠征までにやることを登録しましょう」
- 主ボタン: 「＋ 最初のやることを追加」
- 副導線: 「テンプレから追加」

### AddForm(インライン追加)

リストカードの末尾に置く。画面下に固定していた旧フォームは廃止する。

**未展開時**: 「＋ やることを追加」の行(高さ60px)

**展開時**: 名前の入力欄+「キャンセル」/「登録する」+ヒント「期限は登録後に行から設定できます」

- **追加時に入力するのは名前だけ**にした。遠征前に思いついた順でどんどん足せるようにするため。期限は登録後に行メニューから設定する
- 入力を`trim()`した結果が空の場合は追加せず「TODOの名前を入れてください」(`color-error`)を表示する
- Enterで登録(フォームは開いたまま)、Escapeで閉じる

## 期限当日の強調表示

- 対象: `due_date`が本日の日付と一致し、かつ`is_done=false`の項目(完了済みは強調しない)
- 表示: 行全体の背景を`color-due-today-bg`、左端4pxの縦線を`color-due-today-border`、期限テキストを`color-due-today-text`にし、末尾に「・今日」を付ける
- プッシュ通知等は行わない(F3仕様どおりMVP非対応)

## 状態

| 状態 | 表示 |
|------|------|
| ローディング | 進捗カードとリスト行3本を`paper-track`のスケルトンで表示。読み込み後と同じ余白・行高にしてズレを抑える |
| 空(初回・テンプレ投入前) | 通常は自動投入が即時実行され一瞬で「一覧あり」に遷移する。投入失敗時のみ次の「空(全削除後)」と同じ表示にフォールバックする |
| 空(全削除後、テンプレ投入済みフラグはtrueだが0件) | `EmptyTodo`ブロックを表示。進捗カードは「登録0件」・進捗0%で表示し続ける |
| 一覧あり(通常モード) | `TodoRow`を選択中の並び順モードで表示。当日期限の行は強調表示 |
| 完了済みを隠している | 未完了の行だけを表示し、カードの下に「完了済みn件を非表示中」を出す |
| 手動並べ替えモード | ツールバー右が「並べ替えを終える」だけになる。全行が`TodoRowSortMode`表示になり、インライン追加行は隠す |
| 行メニューを開いている | ボトムシート(名前編集+期限+削除)を表示。背面はスクロールしない |
| 削除直後(5秒間) | 画面下に取り消しトーストを表示 |
| 追加フォーム入力エラー | 入力欄下に「TODOの名前を入れてください」(`color-error`) |
| オフライン | データはIndexedDBのローカル参照のみのため通信不要。オフライン専用の表示分岐は無し |

## タップ時の挙動

| 要素 | 挙動 |
|------|------|
| 行の左側(チェックボックス〜名前・期限) | `is_done`をトグルしIndexedDBへ即時保存 |
| 行の「…」ボタン | 行メニューシート(名前編集+期限+削除)を開く |
| 行メニューの「保存する」 | 名前(空でなければ)と期限を更新しシートを閉じる。名前が空の場合は保存せずエラー表示 |
| 行メニューの「期限を消す」 | 期限日入力をクリアする(「保存する」を押すまで確定しない) |
| 行メニューの「削除する」 | 削除確認に進む |
| 削除確認の「削除する」 | 項目を削除し、残りの`sort_order`を詰め、取り消しトーストを出す |
| トーストの「元に戻す」 | 削除した名前と期限で項目を作り直す。**元の位置ではなく末尾に戻る**(guest-storeに任意位置への挿入APIが無いための仮置き) |
| ツールバーの「並べ替え」 | 並べ替えシートを開く |
| ツールバーの「完了済みを隠す/表示」 | 完了済みの行の表示/非表示を切り替える(保存はしない) |
| 並べ替えシートの選択肢 | 並び順モードを切り替え、localStorageに保存してシートを閉じる |
| 「並べ替えを終える」 | 「期限が近い順」に戻る |
| ドラッグハンドルの長押し→ドラッグ | 約300ms長押し後、指の移動に追従して挿入位置を更新する。離した時点の並びで`sort_order`を振り直す |
| EmptyTodoの「＋ 最初のやることを追加」 | インライン追加フォームを開く |
| EmptyTodoの「テンプレから追加」 | F3テンプレート項目一式(期限未設定)を追加する |
| 「＋ やることを追加」行 / 追従ボタン | インライン追加フォームを開く |
| 追加フォームの「登録する」/ Enter | 名前をバリデーションし、問題なければ末尾に追加してフォームを開いたままにする |

## 遠征当日の利用シーン確認

- 当日は「当日期限の強調」を頼りに片手でチェックしていく想定。強調色(`color-due-today-*`)は一覧を流し見でも視認できるコントラストにする
- 並べ替え・編集・削除は事前準備段階での操作を想定
- 通信不要(IndexedDBのみ)で全操作が成立する

## 不明点・仮置き(完了報告にも記載)

- 手動追加項目の文字数上限30文字は仕様に数値記載が無いため仮置き(`S3a_持ち物.md`・`S2_しおり作成.md`と揃えた)
- 並べ替えは5択のシート方式にし、「期限が近い順」を既定にした。デザイン案の4択には無い選択肢だが、F3「期限が近い順に表示」を落とさないための追加(仮置き)
- 削除の取り消しは同じ内容で作り直す実装のため、元の位置ではなく末尾に戻る(仮置き)
- 追加フォームから期限入力を外し、期限は登録後に行メニューから設定する形にした(仮置き)
- 完了済み(`is_done=true`)項目の扱いは仕様に記載が無い。当初は「位置は変えず見た目のみ変更」としたが、完了済みが上部に残ると直近の未完了TODOが埋もれるというレビュー指摘を受け、「未完了を上部・完了済みを末尾にまとめる」に変更した(仮置き)
- 期限切れ(過去日・未完了)項目の特別な強調は仕様に記載が無いため、当日以外は強調しない扱いとした
- F3テンプレートは仕様上「遠征タイプ別」の記載が無いため、共通1種として扱った(F2は遠征タイプ別テンプレのため差異がある点に注意)
