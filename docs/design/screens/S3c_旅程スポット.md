# S3c 旅程+スポット(旅程タブ)

対応機能: F4(旅程)/ F5(行きたいスポット) / 参照: `docs/01_service_spec.md`
ルーティング: `/shiori/[id]/itinerary`(タブシェルは`S3_しおり詳細.md`参照)。スポットの詳細検索は`/shiori/[id]/spots/search`(S4)へ遷移する
デザイントークン: `docs/design/tokens.md`

## 前提: 1画面内の構成(旅程とスポットの並べ方)

- 旅程タブ(S3c)内を「旅程」「行きたい場所」の2セクションに分け、上部の**セグメントコントロール**で切り替える方式とする(縦積みではなくセクション切替を採用)。
  - 理由: 旅程は遠征当日にチェックしながら使う画面(片手操作・スクロール量の少なさが重要)。スポット一覧を常時同居させると、当日利用時に無関係な一覧を避けて通る必要が生じ実用性を損なう。「当日の予定確認」と「計画時のスポット探し」は用途が異なるため、明確に切り替えられる方式にした
- デフォルト選択: 「旅程」(タブを開いたときの初期表示)
- SegmentedControl: 横並び2ボタン(高さ44px以上、左右余白`space-4`、上下`space-3`)。背景`color-bg-app`。選択中セグメント: 背景`color-primary-soft`・文字`color-primary-soft-text`・`radius-full`。未選択セグメント: 文字`color-text-secondary`・背景なし
- スポットセクションから「旅程に追加」した直後は自動的に「旅程」セグメントに切り替わる(詳細は下記「タップ時の挙動」参照)

## レイアウト(上から順、タブシェル内のコンテンツ領域)

1. **セグメント切替**(「旅程」/「行きたい場所」の2分割)
   - タブバー直下に密着させ、上位タブとの階層関係を示す
   - 選択中は`sakura-ink`の太字+下辺2.5pxのインクバー(タブバーは3px。1段下の階層であることを示すため細くする)
2. **セクション本体**(左右余白`space-6`=24px。持ち物・やることと左端を揃える)

### 旅程セクション

1. ツールバー行: 件数「全4件・2日間」(0件なら「まだ予定がありません」)+「並べ替え」
2. **日ごとのブロック**を日数分。1ブロック = 見出し + カード
   - 見出し(カードの外、`text-heading` / `ink`): 「1日目 8/1(土)」
   - カード(`paper-surface`背景、`paper-border`枠線、`radius-lg`): `EntryRow`を縦積み + 末尾に「＋ 予定を追加」行
   - その日が0件のときはカード内に「この日の予定はまだありません」を出す(追加導線は末尾の行が担う)

### 行きたい場所セクション

1. `AddSpotBar`(「おすすめから探す」/「自由に追加する」の2ボタン)
2. 件数「全n件」(0件なら「まだ登録がありません」)
3. リストカード(`SpotRow`を縦積み)。0件のときは`EmptySpots`の破線カード


## コンポーネント構造

```
<ItineraryTab>
  <SegmentedControl active={section} onChange={setSection}>
    <Segment id="itinerary" label="旅程" />
    <Segment id="spots" label="行きたい場所" />
  </SegmentedControl>
  {section === "itinerary" && <ItinerarySection />}
  {section === "spots" && <SpotSection />}
</ItineraryTab>
```

### ItinerarySection

```
<ItinerarySection>
  <ItineraryToolbar count dayCount sortMode onToggleSort sortAvailable />
  {days.map(day => (
    <DayBlock>
      <h2>1日目 8/1(土)</h2>
      <Card>
        {day.entries.length === 0 ? <EmptyDay />
          : day.entries.map(entry => sortMode
              ? <EntryRowSortMode ... />
              : <EntryRow entry mode highlighted onStartEdit onStartDelete ... />)}
        {addFormOpen && <AddEntryForm onSave onCancel />}
        {!sortMode && !addFormOpen && <AddEntryButtonRow />}
      </Card>
    </DayBlock>
  ))}
</ItinerarySection>
```

#### EntryRow(通常表示、1行)

行高さ72px、左右余白`space-4`。**行全体が1つのボタン**で、タップすると編集(詳細)表示に切り替わる:

1. 時刻(`sakura-ink`の太字13px、幅52px固定)。時刻の桁数に関わらず予定名の左端が揃うよう幅を固定する
2. 予定名(`text-body` / `ink`)
3. 場所(あるとき、ピンのアイコン+`ink-sub`の12.5px)
4. メモ(あるとき、`ink-muted`の12.5px、最大2行)
5. 右端にシェブロン(`ink-faint`)

「旅程に追加」直後の行は`sakura-soft`で一時的に強調し、その位置までスクロールする。

**旧UIにあった行内の編集(✎)・削除(🗑)ボタンは廃止した。** 行全体をタップして開く編集表示に集約する
(右端のシェブロンがその導線であることを示す)。

#### EntryRow(編集/詳細表示)

行が`sakura-tint`背景の入力フォームに置き換わる。上から:

1. 時刻(任意)+「時刻を削除」
2. 予定名 / 場所(任意) / メモ(任意) / 日付(プルダウン)
   - **各入力欄に見出しラベルを付ける。** 5つの入力欄が並ぶため、プレースホルダーだけでは入力後に何の欄か分からなくなる
3. 「キャンセル」+「保存する」
4. 「地図で見る」(場所が入っているときのみ。Google Mapsを別タブで開く)
5. 「この予定を削除する」(`color-error`)

#### EntryRowSortMode(並べ替えモード、1行)

上へ/下へ移動ボタン+予定名。移動できない方向のボタンは`paper-track`背景+`ink-faint`文字で無効を示す。
同じ日の中でのみ移動できる(日をまたぐ並べ替えは不可)。

#### AddEntryForm(予定追加フォーム)

日カードの末尾にインライン表示。編集表示と同じ項目・同じラベルの付け方にする。


### SpotSection

```
<SpotSection>
  <AddSpotBar onFindSeed onOpenFreeForm />
  {freeFormOpen && <FreeSpotForm onSave onCancel />}
  <Count>全n件</Count>
  {rows.length === 0 ? <EmptySpots />
    : <Card>{rows.map(row => <SpotRow row mode ... />)}</Card>}
</SpotSection>
```

#### SpotRow(1行)

1. 訪問済みチェックボックス(24px角丸。チェック済みは`sakura`塗り)
2. 名前(訪問済みは打ち消し線+`ink-done`)、カテゴリバッジ(`sakura-soft`背景)
3. エリア / 「地図で見る」 / 説明 / 注意 / メモ
4. 右側に「旅程に追加」ボタン(白地+`sakura-border`枠+`sakura-ink`文字)と「削除」

「旅程に追加」を押すと行の下に日付・時刻のピッカーが開き、「旅程に追加する」で確定する。
削除は行の下に確認("「<名前>」を削除します。よろしいですか?")を出してから確定する。

#### AddSpotBar

「おすすめから探す」(`sakura`背景の主ボタン)と「自由に追加する」(白地+`sakura-border`枠)の2つ。

#### EmptySpots(空状態)

破線枠のカード。見出し「行きたい場所はまだありません」+説明「聖地やカフェなど、遠征中に寄りたい場所を登録しましょう」。
追加導線は上の`AddSpotBar`が常に出ているため、このカードにはボタンを置かない。

## タップ時の挙動

| 要素 | 挙動 |
|------|------|
| SegmentedControl「旅程」/「行きたい場所」 | 表示セクションを切り替える(データ取得はしない。既に読込済みのローカルデータを出し分けるのみ) |
| 旅程: 「予定を追加」(DayBlock内) | 該当日に`AddEntryForm`をインライン表示する |
| 旅程: 追加フォームの「保存」 | バリデーション後、問題なければ該当日の末尾にエントリーを追加する |
| 旅程: 追加フォームの「キャンセル」 | フォームを閉じ、何も追加しない |
| 旅程: 場所名リンク | `buildGoogleMapsSearchUrl(place_name)`のURLを新規タブで開く |
| 旅程: 編集(鉛筆)ボタン | その行を編集モードにする |
| 旅程: 編集中の保存(✓) | タイトル(空でなければ)・時刻・場所名・メモを更新し通常表示へ戻る。タイトルが空の場合は保存せずエラー表示 |
| 旅程: 編集中の「時刻を削除」 | 時刻入力をクリアする(保存(✓)押下で確定) |
| 旅程: 編集中のキャンセル(×) | 変更を破棄し通常表示へ戻る |
| 旅程: 削除(ゴミ箱)ボタン | その行を削除確認状態にする |
| 旅程: 削除確認中の「削除」 | エントリーを削除し、同じ日の後続エントリーの`sort_order`を詰める |
| 旅程: 削除確認中の「キャンセル」 | 通常表示へ戻る(削除しない) |
| 旅程: ツールバーの「並べ替え」 | 並べ替えモードへ切り替える |
| 旅程: 並べ替えモードの「完了」 | 通常モードへ戻る(この時点の並び順をそのまま保持) |
| 旅程: 上矢印/下矢印ボタン | 同じ日の中で、その項目と隣接する項目の`sort_order`を入れ替える |
| スポット: 「おすすめスポットから探す」 | `/shiori/[id]/spots/search`(S4)へ遷移する |
| スポット: 「自由に追加する」 | `FreeSpotForm`をインライン表示する |
| スポット: 自由入力フォームの「追加」 | バリデーション後、問題なければローカル`spots`(source=ugc/status=private)に保存し`shiori_spots`で紐付ける |

| スポット: 訪問済みチェックボックス | `is_visited`をトグルし即時保存する(保存ボタン不要) |
| スポット: 「地図で見る」リンク | `buildGoogleMapsSearchUrl(spot.name)`のURLを新規タブで開く |
| スポット: 「旅程に追加」ボタン | その行の下に日付/時刻ピッカーをインライン表示する |
| スポット: ピッカーの「追加」 | 選択した日の`itinerary_entries`末尾にエントリーを追加し、SegmentedControlを「旅程」に切り替えて追加行を強調表示する |
| スポット: ピッカーの「キャンセル」 | ピッカーを閉じ、何も追加しない |
| スポット: 削除(ゴミ箱)ボタン | その行を削除確認状態にする |
| スポット: 削除確認中の「削除」 | `shiori_spots`の紐付けを解除する(一覧から消える) |
| スポット: 削除確認中の「キャンセル」 | 通常表示へ戻る(削除しない) |

## 遠征当日の利用シーン確認

- 旅程セクションが当日利用の中心。並べ替え・編集・削除は準備段階での操作を想定し、当日はGoogleマップリンクのタップと閲覧だけで完結できる
- スポットセクションは主に計画段階での利用を想定。当日は「訪問済み」チェックのみで完結できる(並べ替え・編集は無い)
- 旅程CRUD・スポットの自由入力・訪問済みトグル・紐付け解除はIndexedDBのみで完結し通信不要。ただし「おすすめスポットから探す」(S4遷移)・「地図で見る」リンクは外部通信を伴うため、電波が弱い会場では失敗する可能性がある点をS4側にも明記した
- SegmentedControlの2ボタンは高さ44px以上を確保し、片手操作でも押し間違えにくい大きさにした

## 不明点・仮置き

- 旅程/スポットの1画面内の並べ方は**セクション切替(セグメントコントロール)**を採用した(縦積みは当日利用時に無関係なリストが挟まり実用性を損なうため不採用。理由は上記「前提」参照)。仕様(`docs/01_service_spec.md`)に具体的なUI指定は無いため設計判断として仮置き
- 旅程エントリーの並び順は`sort_order`による**手動並べ替えのみ**とし、`time`値による自動並べ替えは行わない。F4仕様には時刻ソートの指定が無く(F3のTODOのみ「期限が近い順」と明記)、S3a持ち物と同じ手動`sort_order`方式に揃えた
- 文字数上限(予定タイトル30文字/場所名50文字/メモ100文字/スポット名30文字/スポットメモ100文字)は仕様に数値記載が無いため仮置き。タイトル系は`S2_しおり作成.md`・`S3a_持ち物.md`・`S3b_TODO.md`の前例(30文字)に揃え、場所名・メモはそれよりやや長い情報を想定し50文字・100文字とした
- スポット削除の範囲は`shiori_spots`の紐付け解除のみとし、`spots`本体(自由入力のugcレコード)は削除しない扱いとした。仕様に削除範囲の明記が無いため仮置き(将来的な再追加・Phase 2の公開申請フローとの整合を優先した)
- スポットの一覧順は「追加順(先頭が最初に追加したもの)」とし、TODOのような自動並べ替えは行わない仮置き。F5仕様に並べ替え・ソート順の記載が無いため
- カテゴリバッジの日本語表示名(聖地/会場/グルメ/グッズ/その他)は`seed-spot`スキルの`category`値(venue/seichi/food/goods/other)に対する仮訳。表示名の指定が仕様に無いため仮置き
- 「旅程に追加」実行時にタイトル・場所名へ流用する値は「スポット名」とした(F4「スポット(F5)から『旅程に追加』できる」の具体的なマッピングが仕様に無いため仮置き)
