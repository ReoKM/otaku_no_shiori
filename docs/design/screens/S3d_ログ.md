# S3d ログ(ログタブ)

対応機能: F6 / 参照: `docs/01_service_spec.md`
ルーティング: `/shiori/[id]/log`(タブシェルは`S3_しおり詳細.md`参照。現在は`ComingSoon`表示のみで、本仕様が実際のコンテンツ)
デザイントークン: `docs/design/tokens.md`

## 前提: データの持ち方(`docs/03_tech_stack.md`・週次計画W2前提を踏まえた設計上の前提)

- 写真本体はIndexedDBの`photos`ストアにBlobとして保存する(ログイン移行時にSupabase Storageへアップロードする設計は`docs/03_tech_stack.md`参照。本画面仕様はゲスト保存前提の表示・操作のみを扱う)
- 1件のログは次の情報を持つ: 写真Blob(必須)/ `day_date`(任意、日付)/ `caption`(任意、ひとことメモ、文字数上限50文字・仮置き。`S2_しおり作成.md`の「目的」欄と同水準で揃えた)
- 写真は**アップロード前にクライアント側(Canvas)で、長辺が1600pxを超える場合のみアスペクト比を維持して長辺1600pxに縮小**してから保存する(1600px以下はリサイズしない=拡大による画質劣化・サイズ増を避ける。`docs/01_service_spec.md` F6 / `docs/03_tech_stack.md`)
- 1しおりあたりの上限は**20枚**(F6仕様の既定値)。上限値そのものは環境変数でのみ変更可能でユーザー設定にはしない(本画面仕様では表示文言の中で数値を扱うが、実際の表示数値は実装側の設定値を参照すること。以下の文言例は既定値20を用いる)

## レイアウト(上から順、タブシェル内のコンテンツ領域)

左右余白は`space-6`(24px)。他タブと左端を揃える。

1. **ツールバー行**
   - 左: 枚数「3/20枚」(`text-body-sm` / `ink-sub`)
   - 右: 「選択」(1枚以上あるときのみ)+「写真を追加」(白地+`sakura-border`枠+`sakura-ink`文字のピル、＋アイコン付き)
   - 選択モード中は「選択をやめる」+「削除(N)」(選択0枚のときは`paper-track`背景で無効表示)
2. **削除確認バー**(「削除(N)」押下時のみ、ツールバー直下にカードで表示。`window.confirm`は使わない)
3. **日付グループ**を日付ごとに
   - 見出し(`text-heading` / `ink`)+ 右に枚数(`ink-muted`)
   - 3列グリッドの写真カード(1:1、`radius-md`、`paper-border`枠)。カード下にメモ(未入力なら「メモを追加」を`ink-faint`で)
4. **共有導線カード**(写真が1枚以上あるときのみ)
   - 「しおりを共有する」+説明+「共有画像を作る」ボタン → S5へ
   - ヘッダーの共有アイコンだけでは意味が伝わりにくいため、写真を見終えた位置に文言つきの導線を置く。S5への入口はこの2つ
5. **広告枠**(F9。破線枠のプレースホルダー)


## 並び順(仕様に指定が無いため仮置き。完了報告にも明記)

- 日付グループは`day_date`の**昇順(古い日付が先)**で並べる。遠征1日目→N日目の順に写真が積み上がっていく「旅の記録」としての読みやすさを優先した
- `day_date`が未設定のログは「日付未設定」グループとして**最後**にまとめる(`S3b_TODO.md`の「期限なしは末尾」と同じ考え方)
- 各グループ内の写真は`created_at`の**昇順**(追加した順)で並べる

## コンポーネント構造

```
<LogTab>
  <Toolbar
    count={photos.length} limit={20}
    selectMode={selectMode} confirming={confirmingDelete} selectedCount={selectedIds.size}
    onAddPhoto onEnterSelectMode onCancelSelectMode onRequestDeleteConfirm onConfirmDelete onCancelConfirm
  />
  <List>
    {photos.length === 0
      ? <EmptyLog onAddPhoto />
      : groupedByDayAsc.map(group => (
          <LogDateGroup key={group.label} label={group.label}>
            <LogPhotoGrid>
              {group.items.map(item =>
                item.status === "processing"
                  ? <LogPhotoCardProcessing key={item.id} />
                  : item.mode === "editing"
                    ? <LogPhotoCardEditing key={item.id} item={item} onSave onCancel />
                    : <LogPhotoCard
                        key={item.id} item={item} onTapEdit
                        selectMode={selectMode} selected={selectedIds.has(item.id)} onToggleSelect
                      />
              )}
            </LogPhotoGrid>
          </LogDateGroup>
        ))}
  </List>
  <AdSlotPlaceholder />
</LogTab>
```

### Toolbar(ツールバー行)

通常時は「選択」(1枚以上あるときのみ)+「写真を追加」。
「選択」を押すと選択モードに入り、「選択をやめる」+「削除(N)」に切り替わる
(各カードに常時🗑ボタンを置く方式は廃止済み)。

「写真を追加」は上限(20枚)到達時に無効表示(`paper-track`背景+`ink-faint`文字)にする。


### LogDateGroup(日付グループ見出し)

- 見出し(`text-heading-md`): 日付がある場合「8/15(土)」形式(月/日+曜日、年は表示しない。`S3b_TODO.md`の期限日表示と同じ形式)、無い場合「日付未設定」
- 見出し下に`LogPhotoGrid`を配置

### LogPhotoGrid(写真グリッド)

- 3列グリッド(`grid-cols-3`、列間・行間`space-2`)。1枚あたり正方形(`aspect-square`、`radius-md`、`object-cover`)
- グリッドは375px幅基準で1枚あたり約109px四方(画面左右余白`space-4`+列間`space-2`×2を差し引いた計算)

### LogPhotoCard(通常状態、1枚)

1. サムネイル画像(正方形、`radius-md`)。画像の上に薄いグラデーションのオーバーレイは不要(装飾を増やさない)
2. 画像の下にキャプション(`text-caption` / `color-text-secondary`、1行`truncate`)。キャプション未設定の場合は「メモを追加」(`color-text-muted`)のプレースホルダー文言を表示する
3. カード全体(画像+キャプション部分)をタップすると編集モードに入る

カードごとの常時削除ボタンは置かない(オーナーフィードバック反映: 一覧が冗長になるため廃止し、下記「写真削除(選択モード)」に一本化した)。

### LogPhotoCard(選択モード中、1枚)

- 右上にチェックのオーバーレイ(円形、選択済みは`color-primary`背景+白いチェックマーク、未選択は薄い背景のみ)
- カード(画像+キャプション部分)をタップすると選択/解除がトグルされる(編集モードには入らない)

### LogPhotoCardProcessing(アップロード中=クライアントリサイズ処理中)

- サムネイル位置に`color-bg-disabled`のスケルトンブロック+中央にスピナー(装飾のみ、ライブラリ非依存の回転アイコンでよい)
- キャプション位置に「処理中…」(`text-caption` / `color-text-muted`)
- タップ操作不可(削除・編集どちらも不可)。リサイズ完了次第、自動的に`LogPhotoCard`(通常状態)に置き換わる

### LogPhotoCardEditing(編集モード)

画像の下に以下を表示(画像自体はそのまま表示、タップでの拡大等は無し):

1. キャプション入力(1行テキスト、プレースホルダー「ひとことメモ(任意)」、文字数上限50文字、入力欄下に右寄せで文字数カウンタ)
2. 日付入力(`<input type="date">`相当、任意)。日付を設定済みの場合は右に「×」クリアボタン(44×44pxタップ領域、`S3b_TODO.md`の期限日クリアと同パターン)
3. 保存(✓)・キャンセル(×)ボタン(各44×44px、横並び)

### 写真削除(選択モード)

1. ツールバーの「削除」タップで選択モードに入る。各`LogPhotoCard`にチェックのオーバーレイが表示され、タップで選択/解除できる。選択モード中は編集・写真追加ともに無効(ツールバーから該当ボタンが消える)
2. ツールバーが「キャンセル」+「削除(N)」(N=選択枚数)に切り替わる。「キャンセル」で選択モードを抜け、選択状態を破棄する
3. 「削除(N)」タップでツールバー直下にインライン確認バーを表示する: 「選択したN枚を削除しますか？」+「削除する」(`color-error`文字)+「キャンセル」(`S3a_持ち物.md`の削除確認と同じインラインパターンだが、対象がツールバー直下である点が異なる。`window.confirm`は使わない)
4. 「削除する」タップで選択した写真をまとめて削除し、選択モードを抜けて通常表示に戻る。「キャンセル」タップで確認バーを閉じ選択モードは維持する(選択状態はそのまま)

### EmptyLog(空状態、写真0枚)

他タブの空状態と同じ破線カード:

- 見出し: 「写真はまだありません」
- 説明: 「遠征中の思い出を、写真とひとことで残しましょう」
- 主ボタン: 「＋ 最初の写真を追加」

### LogShareCard(共有導線カード)

写真が1枚以上あるときだけ、リストの下に置く。

- 見出し: 「しおりを共有する」
- 説明: 「記録した写真とメモから、1枚の共有画像を作れます。」
- ボタン: 「共有画像を作る」→ `/shiori/[id]/share`


## 状態

| 状態 | 表示 |
|------|------|
| ローディング(IndexedDBから`photos`読込中) | リストエリアに`color-bg-disabled`のスケルトン正方形を3×2の6枚分表示 |
| 空(写真0枚) | `EmptyLog`ブロックを表示。広告枠プレースホルダーは通常どおり表示 |
| 一覧あり(通常) | 「並び順」の規則で`LogDateGroup`+`LogPhotoGrid`を表示 |
| アップロード中(クライアントリサイズ処理中) | 選択した写真の枚数分、「日付未設定」グループの末尾に`LogPhotoCardProcessing`を即時追加表示する(処理完了を待たずに「これから追加される」ことを可視化する)。複数枚同時選択時は1枚ずつ処理が完了次第、順次通常カードに置き換わる |
| 上限到達(現在枚数=上限枚数) | Toolbarの「写真を追加」ボタンが非活性表示になる。EmptyLogは表示されない(1枚以上ある前提のため) |
| 選択超過(残り枠より多くのファイルを選択した) | 残り枠数分のみ処理を続行し、超過分は取り込まない。リストエリア上部に一時的な注意文言(`text-body-sm` / `color-error`)を表示: 「上限(20枚)に達したため◯枚のみ追加しました」。数秒後またはユーザーの次操作で自動的に消えてよい(モーダルは使わない) |
| 個別写真の読込・リサイズ失敗 | 該当の`LogPhotoCardProcessing`が「読み込みに失敗しました」(`color-error`、`text-caption`)+×(取り消し)アイコンのカードに置き換わる。タップで一覧から取り除ける(保存済みデータは無いため削除確認は不要) |
| 写真編集中 | 該当カードのみ`LogPhotoCardEditing`表示。他のカードは通常表示のまま |
| 写真選択モード中 | 全カードが選択可能なチェックオーバーレイ付き表示になる。ツールバーが「キャンセル」+「削除(N)」に切り替わる。編集・写真追加は無効 |
| 写真削除確認中(選択モード内) | ツールバー直下にインライン確認バー(「選択したN枚を削除しますか？」+「削除する」+「キャンセル」)を表示。カード一覧の表示は選択モードのまま変わらない |
| キャプション文字数超過 | 入力欄下のカウンタが上限到達を示す(`color-error`)。保存ボタンは押下可能なまま50文字で入力自体を打ち切る(他画面の文字数上限と同じ扱い) |
| オフライン | データはIndexedDBのローカル参照のみのため通信不要。写真の記録・編集・削除は全てオフラインで完結する。広告枠プレースホルダーは中身が無いためオフラインでも表示が変わらない |

## タップ時の挙動

| 要素 | 挙動 |
|------|------|
| Toolbarの「写真を追加」ボタン | ネイティブファイル選択(`accept="image/*" multiple`)を開く。上限到達時は非活性のためタップしても何も起きない |
| ファイル選択後 | 選択された各ファイルについて、残り枠の範囲内でクライアント側リサイズを実行し、`day_date: null` / `caption: null`で`photos`ストアに保存し「日付未設定」グループに追加する。**リサイズは非同期で完了順が前後するため、選択時点で並び順(仮のcreated_at or インデックス)を割り当ててから処理を開始し、画面上の並びがユーザーの選択順と一致するようにする** |
| EmptyLogの「写真を追加」ボタン | Toolbarの「写真を追加」ボタンと同じ挙動 |
| Toolbarの「削除」ボタン(通常時、写真1枚以上) | 選択モードに入る |
| LogPhotoCard(画像+キャプション部分)タップ(通常時) | そのカードを編集モードにする |
| LogPhotoCard(画像+キャプション部分)タップ(選択モード中) | そのカードの選択/解除をトグルする |
| 編集モードの保存(✓) | キャプション(50文字以内)・日付を更新し通常表示へ戻る。更新後、並び順の規則に従い所属グループが変わる場合は該当グループへ移動する |
| 編集モードの「×」(日付クリア) | 日付入力をクリアする(保存はまだ確定しない。保存(✓)押下で確定) |
| 編集モードのキャンセル(×) | 変更を破棄し通常表示へ戻る |
| Toolbarの「キャンセル」ボタン(選択モード中) | 選択モードを抜け、選択状態を破棄する |
| Toolbarの「削除(N)」ボタン(選択モード中) | ツールバー直下にインライン確認バーを表示する(N=0のときは非活性でタップしても何も起きない) |
| 確認バーの「削除する」 | 選択した写真をまとめて削除し、選択モードを抜けて通常表示へ戻る |
| 確認バーの「キャンセル」 | 確認バーを閉じる(選択モード・選択状態は維持する) |
| 読込失敗カードのタップ(×アイコン) | 一覧から取り除く(元々保存されていないため削除処理は発生しない) |
| 広告枠プレースホルダー | タップ不可(中身が無いため) |

## 遠征当日の利用シーン確認

- 片手操作: 「写真を追加」ボタンは画面上部右側に固定し親指で届きやすい位置に置く。削除アイコンも44×44pxを確保し誤タップしにくくする
- 移動中/電波弱い: 撮影〜保存まで完全にオフライン(IndexedDBのみ)で完結する。「アップロード中」の名称はクライアント側リサイズ処理を指し、ネットワーク通信は発生しない
- 会場・移動中に複数枚まとめて撮った写真を一度に選択しても、上限を超えた分は自動的に弾かれ、エラーで操作全体が止まることはない(選択超過時も残り枠分は保存される)

## 不明点・仮置き(完了報告にも記載)

- ログ一覧の並び順(日付グループ昇順+グループ内`created_at`昇順、日付未設定は末尾)は仕様に指定が無いため仮置き
- キャプション文字数上限50文字は仕様に数値指定が無いため、`S2_しおり作成.md`の「目的」欄と同水準で仮置き
- 「写真を追加」タップ後にキャプション/日付を先に入力させず、まず写真を保存してからカードをタップして後編集する方式とした(ネイティブファイル選択の直後にモーダルを挟まない方が遠征中の片手操作に向くと判断。仕様に手順の指定は無い)
- 選択超過時の注意文言表示時間(自動で消えるまでの秒数)は仕様に指定が無いため具体的な秒数は定めず、フロント実装側の裁量とした
