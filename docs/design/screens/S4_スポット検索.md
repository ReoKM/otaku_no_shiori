# S4 スポット検索

対応機能: F5(行きたいスポット、シードスポットの検索・追加) / 参照: `docs/01_service_spec.md`
ルーティング: 一覧 `/shiori/[id]/spots/search` / 詳細 `/shiori/[id]/spots/search/[spotId]`(`spotId`は`seed-`プレフィックス付きID)
デザイントークン: `docs/design/tokens.md`

S3c(旅程タブ)の「行きたい場所」セクションから「シードスポットから探す」ボタンで遷移してくる画面。運営シードスポット(同梱JSON、`seeds/spots/`由来、ビルド時にアプリへバンドル)を検索・一覧表示し、詳細画面から「しおりに追加」する。

## レイアウト(上から順)

### 一覧画面(`/shiori/[id]/spots/search`)

1. **ヘッダー**(`sticky top-0`、背景`color-bg-surface`、下境界`color-border-default`)
   - 左: 戻るボタン(`<`アイコン、44×44px) → S3c(`/shiori/[id]/itinerary`)へ遷移し、「行きたい場所」セグメントを選択した状態で表示する(追加結果がすぐ見えるようにするため)
   - 中央: 画面タイトル(`text-heading-lg`): 「スポットを探す」
2. **検索バー**(左右余白`space-4`、上下`space-3`)
   - テキスト入力(プレースホルダー「スポット名・エリアで検索」、虫眼鏡アイコン付き)
   - 入力の都度リアルタイムに絞り込む(送信ボタンは無し)
3. **カテゴリフィルターチップ行**(横スクロール可、左右余白`space-4`、チップ間`space-2`)
   - 「すべて」「会場」「聖地」「グルメ」「グッズ」「その他」の6チップ、単一選択
   - 選択中チップ: 背景`color-primary-soft`・文字`color-primary-soft-text`・`radius-full`
   - 未選択チップ: 背景なし・枠線`color-border-default`・文字`color-text-secondary`・`radius-full`
   - デフォルト選択: 「すべて」
4. **検索結果件数表示**(左右余白`space-4`、上下`space-2`、`text-body-sm` / `color-text-secondary`): 「12件」
5. **結果リストエリア**(縦スクロール、項目間`color-border-default`の1px区切り線)
   - 0件の場合: `EmptySearchResult`ブロック
   - 1件以上の場合: `SpotCard`を並び順(下記「並び順」参照)で縦積み

### 詳細画面(`/shiori/[id]/spots/search/[spotId]`)

1. **ヘッダー**
   - 左: 戻るボタン(44×44px) → 一覧画面(`/shiori/[id]/spots/search`、検索条件は保持したまま)へ戻る
   - 中央: 画面タイトル(`text-heading-lg`、1行省略`truncate`): スポット名
2. **詳細コンテンツ**(左右余白`space-4`、上下`space-4`)
   - カテゴリバッジ + エリア
   - 「地図で見る」リンク
   - オタク文脈の説明(`description`、`text-body`)
   - 注意書き(`caution`設定時のみ、`color-error`背景`color-error-bg`のブロック)
3. **フッター固定エリア**(`sticky bottom-0`、背景`color-bg-surface`、上境界`color-border-default`、内側パディング`space-4`)
   - 「しおりに追加」ボタン(未追加時)/「追加済み」表示(追加済み時)

## 並び順(仮置き)

一覧の並び順は仕様(`docs/01_service_spec.md`)に指定が無いため、次の順で仮置きする(完了報告に明記):

1. **カテゴリ順**: `venue`(会場) → `seichi`(聖地) → `food`(グルメ) → `goods`(グッズ) → `other`(その他)。`seed-spot`スキルのJSONスキーマに列挙されている順序をそのまま採用した
2. カテゴリが同じ場合は**名前順**(日本語ロケールの文字列比較、`localeCompare('ja')`相当)

カテゴリフィルターで絞り込んだ場合も、フィルター後の結果に同じ並び順(この場合は実質「名前順」のみ)を適用する。

## コンポーネント構造

```
<SpotSearchList>
  <Header><BackButton /><Title>スポットを探す</Title></Header>
  <SearchBar value={keyword} onChange={setKeyword} />
  <CategoryChips active={category} onChange={setCategory} />
  <ResultCount count={results.length} />
  <List>
    {results.length === 0
      ? <EmptySearchResult keyword={keyword} onBackToShiori />
      : results.map(spot => (
          <SpotCard
            spot={spot}
            added={isAdded(spot.id)}
            onTap={() => router.push(`/shiori/${id}/spots/search/${spot.id}`)}
          />
        ))}
  </List>
</SpotSearchList>

<SpotSearchDetail>
  <Header><BackButton /><Title>{spot.name}</Title></Header>
  <DetailBody spot={spot} />
  <FooterBar>
    {added
      ? <AddedIndicator />
      : <Button primary onTap={onAddToShiori}>しおりに追加</Button>}
  </FooterBar>
</SpotSearchDetail>
```

### SpotCard(一覧の1行)

縦積み構成、左右余白`space-4`、上下パディング`space-3`、下境界`color-border-default`。行全体がタップ領域(詳細画面へ遷移)。

1. 1行目(横並び): 名前(`text-body`、太字) + カテゴリバッジ(チップ: 背景`color-primary-soft`・文字`color-primary-soft-text`・`radius-full`。ラベルは「会場」「聖地」「グルメ」「グッズ」「その他」) + 追加済みの場合「追加済み」バッジ(背景`color-bg-disabled`・文字`color-text-disabled`・`radius-full`)
2. 2行目: エリア(`text-body-sm` / `color-text-secondary`)
3. 3行目: オタク文脈の説明(`text-caption` / `color-text-secondary`、2行までで省略`line-clamp-2`)
4. 注意書きがある場合、末尾に「⚠ 注意あり」の短いラベル(`text-caption` / `color-error`)のみ表示(本文は詳細画面で確認させる)

### DetailBody(詳細画面のコンテンツ)

- 名前(ヘッダーに表示済みのため本文では省略)
- カテゴリバッジ + エリア(横並び、`space-2`間隔)
- 「地図で見る」リンク(`text-body-sm` / `color-primary`)。タップで`buildGoogleMapsSearchUrl(spot.map_query || spot.name)`(`src/lib/googleMapsUrl.ts`)のURLを新規タブで開く
- 見出し「このスポットについて」(`text-heading-md`) + オタク文脈の説明(`description`、`text-body`、複数行可)
- 注意書き(`caution`設定時のみ): 見出し無しで「⚠ {caution本文}」を`color-error`文字・`color-error-bg`背景・`radius-md`のブロックで表示

### AddedIndicator(追加済み表示、詳細画面フッター)

- チェックアイコン + 「追加済み」(`text-button` / `color-text-disabled`)。タップ不可(非活性ボタン相当の見た目)
- その右に「追加を取り消す」テキストボタン(`text-caption` / `color-text-secondary`、44pxタップ領域)を置く。タップで`shiori_spots`の紐付けを解除し「しおりに追加」ボタン表示に戻す(誤操作直後にS3cへ戻らず取り消せるようにする。レビュー指摘反映。シードスポットは`spots`ストアに実体を持たないため紐付け解除のみでよい。確認ダイアログは挟まない=追加し直しが容易なため)
- 整理済みの削除導線(メモ・訪問済み状態を持つスポットの削除)はS3c側に一本化する方針は維持する

### EmptySearchResult(検索結果0件)

- 説明文(`text-body` / `color-text-secondary`): 「該当するスポットが見つかりませんでした」
- 補足文(`text-body-sm` / `color-text-secondary`): 「キーワードやカテゴリを変えて探してみてください」
- リンクボタン(`color-primary`テキストボタン): 「しおりに戻って自由に追加する」→ S3c(`/shiori/[id]/itinerary`)へ遷移し、「行きたい場所」セグメントの自由入力フォームが開いた状態で表示する

## 状態

| 状態 | 表示 |
|------|------|
| ローディング(同梱シードJSON読込・既存`shiori_spots`との突合中) | 結果リストエリアに`color-bg-disabled`のスケルトン行を3本表示。検索バー・カテゴリチップは表示するが操作不可(`opacity-50`) |
| 初期(画面を開いた直後、キーワード未入力) | カテゴリ「すべて」でシードデータ全件を並び順どおりに表示する(検索してから見るのではなく、最初から一覧を見せる) |
| 入力中(キーワード入力・カテゴリ変更) | 入力の都度、結果リストと件数表示がリアルタイムに更新される |
| 検索結果0件 | `EmptySearchResult`ブロックを表示 |
| 完了(結果表示中、通常) | `SpotCard`を並び順で表示。追加済みのスポットには「追加済み」バッジを表示する |
| 詳細画面表示中 | `DetailBody`+フッターの「しおりに追加」ボタンまたは「追加済み」表示 |
| 追加処理中(しおりに追加ボタン押下直後) | ボタンを一時的に非活性にし、処理完了後すぐ「追加済み」表示に切り替える(IndexedDB書き込みのみのため体感遅延はほぼ無い想定) |
| 追加済み | フッターが`AddedIndicator`(「追加済み」+チェックアイコン)に変わる。一覧画面に戻ってもそのスポットのカードに「追加済み」バッジが付いた状態で表示される |
| オフライン | シードデータは同梱JSON(ビルド時にアプリへ同梱済み)のため、検索・一覧・詳細閲覧・しおりへの追加(IndexedDB書き込み)はすべて通信不要でオフラインでも成立する。「地図で見る」リンクのみ外部通信を伴うため、電波が弱い環境ではタップ後の地図表示が失敗する可能性がある |

## タップ時の挙動

| 要素 | 挙動 |
|------|------|
| ヘッダーの戻るボタン(一覧画面) | S3c(`/shiori/[id]/itinerary`)へ遷移し、「行きたい場所」セグメントを選択した状態で表示する |
| ヘッダーの戻るボタン(詳細画面) | 一覧画面(`/shiori/[id]/spots/search`)へ戻る。検索キーワード・カテゴリフィルターの選択状態は保持する |
| 検索バーへの入力 | キーワードでリアルタイムに結果を絞り込む(名前・エリア・説明文に部分一致) |
| カテゴリチップ | タップしたカテゴリのみに結果を絞り込む(単一選択)。「すべて」タップで絞り込み解除 |
| SpotCard(行全体) | 詳細画面(`/shiori/[id]/spots/search/[spotId]`)へ遷移する |
| 「地図で見る」リンク(詳細画面) | `buildGoogleMapsSearchUrl(spot.map_query || spot.name)`のURLを新規タブで開く |
| 「しおりに追加」ボタン(詳細画面) | 該当しおりの`shiori_spots`に`spot_id=該当のseed-プレフィックス付きID`・`memo=null`・`is_visited=false`で新規追加する(シードスポット自体は`spots`ストアへ複製保存しない)。追加後、フッターが`AddedIndicator`に変わる |

※参照整合性の注記(レビュー指摘反映): IndexedDBには外部キー制約が無いため、ゲスト利用中は`shiori_spots.spot_id`が`spots`ストアに存在しない`seed-`IDを指しても問題ない。ただしクラウド側(`supabase/migrations/0001`)の`shiori_spots.spot_id`は`spots`テーブルへの外部キーを持つため、**W3のゲスト→ログイン移行時には、`seed-`IDを参照する`shiori_spots`より先にシードスポットをサーバーの`spots`テーブル(source='seed')へ投入し、IDをマッピングする処理が必要**になる。この移行手順はW3のF8実装タスクで扱う(このファイルでは設計上の前提として記録するのみ)。
| `EmptySearchResult`の「しおりに戻って自由に追加する」 | S3c(`/shiori/[id]/itinerary`)へ遷移し、「行きたい場所」セグメントの自由入力フォームを開いた状態で表示する |

## 遠征当日の利用シーン確認

- S4は主に計画段階(遠征前)での利用を想定した画面であり、当日の利用シーンは想定しない(F5「行きたいスポット」は計画時の情報収集用途のため)
- ただし通信状況に関わらず動作することは重要(準備は移動中・電波が弱い場所でも行うため): シードデータが同梱JSONのため、検索・一覧・詳細閲覧・しおりへの追加はすべてオフラインで成立する設計にした
- 検索バー・カテゴリチップ・カード・ボタンはいずれも44px以上のタップ領域を確保し、移動中の片手操作でも押しやすくした

## 不明点・仮置き

- **一覧の並び順**は仕様に指定が無いため「カテゴリ順(venue→seichi→food→goods→other)→名前順」で仮置きした。カテゴリ順は`seed-spot`スキルのJSONスキーマの列挙順をそのまま採用した(完了条件に明記の指示どおり)
- 検索は名前・エリア・説明文への部分一致とした(仕様に検索対象フィールドの指定が無いため仮置き)。オタク文脈の`description`も検索対象に含めることで、作品名・キャラ名での検索にもヒットしやすくする狙い
- `description`(オタク文脈)は一覧カードでは2行に省略表示、詳細画面では全文表示という構成にした(仕様に表示位置の指定が無いため仮置き)。一覧では発見・興味喚起のためのフック、詳細では実際に追加判断する材料という役割分担
- `caution`(注意書き)は一覧カードでは「⚠ 注意あり」の短いラベルのみとし、本文は詳細画面でのみ表示する仮置きとした。一覧行を簡潔に保ちつつ、注意点の存在自体は見落とされないようにする狙い
- 詳細画面の「しおりに追加」後の導線は、S4内に留まり「追加済み」表示にするだけとし、S3cへの自動遷移は行わない仮置きとした(検索セッション中に複数スポットを続けて追加できるようにするため。1件追加するたびにS3cへ戻されると再検索の手間が増えるため)
- 「追加済み」スポットをS4から直接削除・取り消しする操作は用意しない仮置きとした(削除操作はS3cの「行きたい場所」セクションに一本化し、S4は追加専用の画面として役割を絞った)
- `refs`(出典URL)は運営向けの出典情報であり、本画面ではユーザーに表示しない仮置きとした(F5仕様に出典表示の要求が無く、外部リンクを増やすと当日利用時の誤タップリスクにもなるため)
