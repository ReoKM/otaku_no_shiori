# S5 共有画像プレビュー

対応機能: F7(共有画像生成) / F8(ログイン促し・一言のみ) / 参照: `docs/01_service_spec.md`
ルーティング: `/shiori/[id]/share`
デザイントークン: `docs/design/tokens.md`

## 前提

- 本仕様は**S5画面そのもの**(テンプレ選択→プレビュー→保存)を対象とする。「共有画像を作る」ボタンをS3のどのタブ・どの位置に置くかは本タスク(Issue #36)のスコープ外。S3側に導線が無くてもW2内では`/shiori/[id]/share`への直接遷移で確認できる状態でよい(frontend-dev裁量。将来S3側にボタンを追加する際は本画面へ遷移するだけでよい)
- 画像生成はNetlify Function(satori+resvg、週次計画W2タスク#11)がPNGを返す想定。本仕様はそのFunctionの入出力仕様は定義せず、S5画面の状態遷移・表示のみを扱う
- 画像に含む非写真コンテンツ(タイトル/日程/遠征タイプ/旅程ダイジェスト/持ち物・スポットの一部)は`docs/01_service_spec.md` F7のとおりしおりデータから**自動抽出**し、本画面上でユーザーが個別に選ぶUIは設けない。ユーザーが画面上で明示的に選べるのは**テンプレート(シンプル/にぎやか)**と**写真(0〜3枚)**の2つのみ(仮置き。理由は「不明点・仮置き」参照)
- 写真の選択肢は`S3d_ログ.md`で記録された写真(IndexedDBの`photos`ストア)一覧から出す。ログに写真が0枚の場合、画像は写真なしで生成される(F7「写真(任意1〜3枚)」のとおり任意)

## レイアウト(上から順)

1. **ヘッダー**(`sticky top-0`、背景`color-bg-surface`、下境界`color-border-default`)
   - 左: 戻るボタン(`<`アイコン、44×44pxタップ領域)。前の画面へ戻る(遷移元がどこであっても直前の画面に戻る=ブラウザ履歴のback相当)
   - 中央: タイトル「共有画像を作る」(`text-heading-lg`)
2. **メインエリア**(左右余白`space-4`、上下`space-4`、セクション間`space-8`)
   - 状態により「選択フォーム(テンプレ+写真選択)」または「生成中」または「生成失敗」または「プレビュー」を表示(下記「状態」参照)
3. **送信エリア(選択フォーム表示中のみ、画面下部固定)**(`sticky bottom-0`、背景`color-bg-surface`、上境界`color-border-default`、内側パディング`space-4`)
   - 「共有画像を作成」ボタン(幅いっぱい、高さ44px以上)

## コンポーネント構造

```
<Header>
  <BackButton />
  <Title text="共有画像を作る" />
</Header>
<Main>
  {screenState === "selecting" && (
    <SelectForm>
      <TemplateSection selected={template} onSelect />
      <PhotoSection photos={logPhotos} selected={selectedPhotoIds} onToggle max={3} />
      <SubmitBar>
        <GenerateButton label="共有画像を作成" onTap={generate} />
      </SubmitBar>
    </SelectForm>
  )}
  {screenState === "generating" && <GeneratingBlock />}
  {screenState === "failed" && <FailedBlock onRetry={generate} />}
  {screenState === "preview" && (
    <PreviewBlock image={generatedImage}>
      <SaveButton onTap={saveOrShare} />
      <LoginHint />
    </PreviewBlock>
  )}
</Main>
```

### TemplateSection(テンプレート選択、Step1)

- 見出し(`text-heading-md`): 「テンプレートを選ぶ」
- 単一選択カード2枚(縦並び、各カード`radius-lg`・`color-border-default`枠・内側パディング`space-4`)
  - 左側: 9:16の縦長スウォッチ(装飾のみ、実際のテンプレ最終デザインとは異なる仮のイメージ。幅48px程度、`radius-md`)
    - シンプル: `color-bg-app`背景に「Aa」の文字だけを中央配置(文字中心の落ち着いた見た目を示す仮アイコン)
    - にぎやか: `color-primary-soft`背景に「✨」「🎀」を散らした仮アイコン(装飾多めの見た目を示す)
  - 右側: テンプレート名(`text-body` font-semibold)+一行説明(`text-body-sm` / `color-text-secondary`)
    - シンプル: 「写真中心の落ち着いたデザイン」
    - にぎやか: 「絵文字や装飾多めの賑やかなデザイン」
  - 選択中カード: `color-primary`の2px枠+`color-primary-soft`背景。未選択カード: `color-border-default`枠+`color-bg-surface`背景
  - 初期選択: 「シンプル」

### PhotoSection(写真選択、Step2・任意)

- 見出し(`text-heading-md`): 「写真を選ぶ(任意・最大3枚)」
- 選択件数表示(`text-body-sm` / `color-text-secondary`): 「1/3枚選択中」
- ログに保存済みの写真をサムネイルグリッドで表示(3列グリッド、`S3d_ログ.md`の`LogPhotoGrid`と同じ見た目)。各サムネイル右上に選択チェックマーク(未選択時は非表示、選択時は`color-primary`背景の丸チェックアイコン)
- サムネイルをタップすると選択トグル。3枚選択済みの状態で4枚目をタップした場合は選択されず、見出し付近に一時的な注意文言(`text-body-sm` / `color-error`)「写真は3枚まで選べます」を表示する(数秒後またはユーザーの次操作で消えてよい。モーダルは使わない)
- ログの写真が0枚の場合: グリッドの代わりに説明文(`text-body-sm` / `color-text-secondary`)「ログに写真を追加すると、ここから選べます」を表示する(このセクション自体は非表示にしない。写真無しでも画像は生成できるため)

### GenerateButton(送信エリア)

- ラベル: 「共有画像を作成」(`color-primary`背景、幅いっぱい、44px以上)
- タップで生成処理を開始し、画面状態を「生成中」に切り替える

### GeneratingBlock(生成中)

- 画面中央に配置(上下`space-10`)
- スピナー(装飾のみ)
- 見出し(`text-heading-md`): 「画像を作成しています…」
- 補足文(`text-body-sm` / `color-text-secondary`): 「電波が弱い場所では時間がかかる場合があります」
- 操作要素は置かない(キャンセル導線は無し。仕様に指定が無いため設けない)

### FailedBlock(生成失敗)

- 画面中央に配置
- 見出し(`text-heading-md` / `color-error`): 「画像の作成に失敗しました」
- 補足文(`text-body-sm` / `color-text-secondary`): 「時間をおいてもう一度お試しください」
- ボタン(`color-primary`背景、`radius-md`): 「もう一度試す」
  - タップすると選択フォーム(Step1・Step2の選択内容は保持したまま)に戻り、再度生成処理を実行できる状態にする

### PreviewBlock(プレビュー完了)

1. 生成された画像(縦長9:16、幅は画面いっぱい〜左右`space-4`余白、`radius-lg`、`color-border-default`の1px枠)
2. 画像下の説明文(`text-body-sm` / `color-text-secondary`): 「保存した画像はご自身でX/Instagramなどに投稿してください」(F7「画像保存→手動投稿」を明示する)
3. 保存ボタン(`SaveButton`、下記参照)
4. 保存ボタン下の恒久表示ガイダンス(`text-caption` / `color-text-muted`): 「保存できない場合は、画像を長押しして「画像を保存」を選んでください」(モバイルの`download`属性が機能しない場合の手動保存フォールバック。常に表示し、保存方式の成否に関わらず消さない)
5. テキストボタン(`text-body-sm` / `color-primary`): 「テンプレートを選び直す」
   - タップすると選択フォーム(Step1・Step2)に戻る。直前の選択内容(テンプレート・選択写真)は保持したまま再表示する
6. `LoginHint`(F8・一言のみ、下記参照)

### SaveButton(保存ボタン、機能分岐)

画面表示・タップ挙動は次の優先順位で分岐する(判定はプレビュー表示時に1回行う)。

1. **Web Share API(ファイル共有)が使える場合**(`navigator.share`が存在し、かつ`navigator.canShare`が無いか`canShare({ files })`が`true`を返す環境。iOS Safari 15.4以降・多くのAndroid Chromeが該当)
   - ボタン文言: 「保存 / 共有」
   - タップで生成画像ファイルを添えて`navigator.share()`を呼び、端末のOS共有シートを開く(ユーザーが「写真に保存」や共有先アプリを選ぶ)
2. **上記が使えない場合**(主にPC版ブラウザ、一部の古いモバイルブラウザ)
   - ボタン文言: 「画像を保存」
   - タップで生成画像のBlob URLに対し`<a download>`相当のダウンロードを実行する

いずれの分岐でも、タップ後は下記「保存済み」状態に遷移する(保存自体の成否はブラウザ・OS側の挙動に依存し検知できないため、「保存操作を実行したこと」を示す表示にとどめる。詳細は「不明点・仮置き」参照)。

### LoginHint(F8ログイン促し・一言のみ)

- プレビュー完了状態でのみ、`LoginHint`に達したら1回表示する(常時表示ではなく画像生成後にのみ現れる。`docs/01_service_spec.md` F8「共有画像生成後の一言」に対応)
- 見た目: ボタンではなくテキスト行(`text-body-sm` / `color-text-secondary`、先頭に💡装飾)。タップ不可・遷移導線なし(S6はW3未実装のため)
- 文言: 「💡 ログインすると、しおりを他の端末からも見られるようになります」

## 状態

| 状態 | 表示 |
|------|------|
| 選択(初期表示) | `TemplateSection`(初期選択: シンプル)+`PhotoSection`+送信エリアの「共有画像を作成」ボタン |
| 写真選択超過 | `PhotoSection`見出し付近に「写真は3枚まで選べます」(`color-error`)を一時表示 |
| 生成中 | `GeneratingBlock`のみ表示(選択フォームは隠す)。送信エリアも隠す |
| 生成失敗 | `FailedBlock`のみ表示。「もう一度試す」タップで選択状態に戻る(選択内容は保持) |
| プレビュー完了 | `PreviewBlock`表示(画像+手動投稿の説明文+保存ボタン+長押し保存ガイダンス+「テンプレートを選び直す」+`LoginHint`) |
| 保存済み(保存ボタンをタップ済み) | 保存ボタンの下に確認表示(`text-body-sm` / `color-primary`)「✓ 保存を開始しました」を追加表示する。ボタン自体は非活性にせず、再タップ可能なままにする(共有シートを閉じてしまった場合や保存先を変えたい場合に再試行できるようにするため) |
| しおりが見つからない(不正なid) | メインエリアに「このしおりは見つかりませんでした」(`color-error`)+「一覧に戻る」ボタン(`/`へ遷移)。`S3_しおり詳細.md`の同パターンを踏襲 |
| オフライン | テンプレート選択・写真選択(ログはIndexedDB参照のみ)は通信不要。画像生成(Netlify Function呼び出し)は通信が必要なため、オフライン時に生成をタップすると「生成失敗」状態と同じ表示(補足文を「電波の状態を確認してもう一度お試しください」に差し替え)にする |

## タップ時の挙動

| 要素 | 挙動 |
|------|------|
| 戻るボタン | 直前の画面へ戻る |
| テンプレートカード(シンプル/にぎやか) | そのテンプレートを選択状態にする(単一選択) |
| 写真サムネイル(3枚未満選択時) | そのログ写真を選択状態にする |
| 写真サムネイル(3枚選択済みで4枚目をタップ) | 選択されない。「写真は3枚まで選べます」を一時表示する |
| 選択済み写真サムネイルの再タップ | 選択解除する |
| 「共有画像を作成」ボタン | 生成処理を開始し「生成中」状態へ遷移する |
| 「もう一度試す」ボタン(生成失敗時) | 選択状態(直前の選択を保持)に戻り、生成処理を再実行できるようにする |
| 「テンプレートを選び直す」(プレビュー時) | 選択状態(直前のテンプレート・写真選択を保持)に戻る。生成済み画像は破棄される |
| 保存ボタン(「保存 / 共有」または「画像を保存」) | Web Share APIが使える環境ではOS共有シートを開く。使えない環境ではBlobダウンロードを実行する。いずれも実行後「保存済み」の確認表示を追加する |
| 「一覧に戻る」ボタン(しおり未検出時) | `/`(S1)へ遷移 |
| `LoginHint` | タップ不可(導線なし) |

## 遠征当日の利用シーン確認

- 片手操作: テンプレートカード・写真サムネイル・各ボタンはいずれも44px以上のタップ領域を確保。プレビュー画面の主要ボタン(保存)は画面下部寄りに配置し親指で届く位置にする
- 移動中/電波弱い: 画像生成のみNetlify Functionへの通信が必要なため、オフライン時は生成失敗と同様の表示にフォールバックする(通信復帰後に「もう一度試す」で再実行できる)。テンプレ・写真の選択操作自体は通信不要
- 保存操作はOS標準機能(共有シート/ダウンロード/長押し保存)に委ね、アプリ独自の複雑な保存UIを作らない(遠征後の限られた電波・バッテリーでも完結できるようにするため)

## 不明点・仮置き(完了報告にも記載)

- 画像に含む非写真コンテンツ(タイトル/日程/遠征タイプ/旅程ダイジェスト/持ち物・スポットの一部)は、しおりデータからの自動抽出のみとし、本画面上でユーザーが個別に選ぶUIを設けない仕様とした。仕様(F7)には「画像に含む内容」の列挙はあるが、抽出範囲や取捨選択をユーザーが操作できるとは書かれていないため、MVPでは自動抽出+写真のみ手動選択という最小構成にした(「迷ったら削る」の原則に沿う)
- テンプレートの一行説明文・仮スウォッチ(「Aa」「✨🎀」)は最終的なデザイントーンを規定するものではなく、選択肢を区別するための仮のUI表現。実際のテンプレート見た目は`share-image-designer`(週次計画タスク#7)が決定する
- 写真選択の上限3枚は仕様(F7「写真(任意1〜3枚)」)に明記済みのためそのまま採用(仮置きではない)
- 「保存済み」状態はOS側の保存・共有操作の成否を検知できないため、「保存操作を実行したこと」を示す表示にとどめている(確実な保存完了通知ではない)。この点は仕様に記載が無いため設計判断として仮置きした
- 生成中のキャンセル導線は仕様に指定が無いため設けなかった
- オフライン時の画像生成の扱い(生成失敗と同表示にフォールバック)は仕様に明記が無いため仮置きした
