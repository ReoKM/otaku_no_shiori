# S6 設定/アカウント

対応機能: F8 / 参照: `docs/01_service_spec.md`
ルーティング: `/settings`(仮置き。仕様にパス名の指定が無いため。詳細は「不明点・仮置き」参照)
デザイントークン: `docs/design/tokens.md`

## 前提

- W1時点の`S1_ホーム一覧.md`には「S6はW1未実装のためヘッダーに設定導線は置かない」という注記がある。本ドキュメントでS6が定義されたことに伴い、**S1ヘッダー右側に設定導線(歯車アイコン、44×44pxタップ領域)を追加する**ことを前提とする。ただしS1ヘッダーの実装変更そのものは本Issue(#92)のスコープ外(`S1_ホーム一覧.md`側の改訂と実装が別途必要)。詳細は「不明点・仮置き」参照
- `S5_共有画像プレビュー.md`の「LoginHint」は現状「タップ不可・遷移導線なし(S6はW3未実装のため)」と定義されている。S6が実装された後はこのヒント文言をタップ可能にしS6へ遷移させる余地があるが、**S5側の改訂も本Issueのスコープ外**とする
- ログイン状態の判定・OAuthコールバックのエラー伝達方法・移行処理の進捗取得方法は、いずれもF8スプリントの他タスク(#93セッション更新middleware・#94 OAuthコールバック・#97〜#99移行API・移行フロー結線)が確定させる実装詳細である。本ドキュメントはUIの見た目・状態・文言のみを定義し、状態を渡す具体的なデータ構造(props/contextの形)はfrontend-dev実装時に上記タスクとすり合わせる前提とする
- F9(広告枠)はしおり一覧下部・ログ画面下部の2箇所限定(`docs/01_service_spec.md`)。S6には広告枠を置かない

## レイアウト(上から順)

配色・書体・角丸は`docs/design/tokens.md`の紙テイストトークンに従う。左右余白は`space-6`(24px)でS2・S3と揃える。

1. **ヘッダー**(`sticky top-0`、`paper-surface`背景、下端に`paper-border`)
   - 左に戻るボタン(44×44px) → 直前の画面(通常はS1)へ戻る
   - 中央に「設定」(20px / 900)
2. **アカウントセクション**(未ログイン/ログイン済みで内容が切り替わる。詳細は下記コンポーネント構造)
3. **データ移行状態カード**(ログイン済み、かつ移行対象データがある場合のみ表示)
4. **利用規約・プライバシーポリシーリンク**(常時表示。S1フッターと同じ文言・遷移先で揃える)

## コンポーネント構造

```
<Header>
  <BackButton />
  <Title text="設定" />
</Header>
<Main>
  {authState === "loggedOut" && (
    <LoggedOutSection>
      <GuestNotice />           // 「今のままでも使えます」の説明
      <LoginButtonX />
      <LoginButtonGoogle />
      <LoginErrorNotice />      // ログイン失敗時のみ
      <OfflineNotice />         // オフライン時のみ
    </LoggedOutSection>
  )}
  {authState === "loggedIn" && (
    <LoggedInSection>
      <AccountStatusRow />      // ログイン中プロバイダ表示
      <MigrationStatusCard />   // 移行対象がある場合のみ
      <LogoutButton />
    </LoggedInSection>
  )}
  <LegalLinks>
    <LinkToTerms />
    <LinkToPrivacy />
  </LegalLinks>
</Main>
```

### LoggedOutSection(未ログイン状態)

1. `GuestNotice`(説明ブロック。カード化はせず地の文で置く)
   - 見出し(16px / 900 / `ink`): 「ログインしてクラウド保存」
   - 説明(13px / `ink-sub` / 行間1.9): 「ログインすると、しおりが自動でクラウドに保存され、機種変更や別の端末からも見られるようになります。」
   - 補足(12px / `ink-muted`): 「今のまま(ログインなし)でも、しおりの作成・編集はすべて使えます。データはこの端末だけに保存されます。」
2. `LoginButtonX` / `LoginButtonGoogle`(縦に`space-3`間隔で並べる、この順)
   - 共通仕様: 全幅、高さ48px以上、`radius-btn`(14px)、`paper-surface`背景、`paper-border`枠(1.5px)、アイコン(24px、左寄せ)+ラベル(`text-button`: 15px/700、`ink`)を横並び中央寄せ
   - アイコンはX/Googleの公式ロゴマーク(Xは`ink`トークンでのモノクロ表示、Googleは公式4色の"G"ロゴをそのまま使用)。**この2アイコンのみ本トークン体系の対象外**(第三者ブランドの公式アセットのため。詳細は「不明点・仮置き」参照)
   - ボタン自体の背景・枠線・文字色はいずれもトークンで指定し、生の16進数は使わない
3. `LoginErrorNotice`(ログインに失敗して`/settings`に戻ってきた場合のみ表示)
   - `paper-surface`背景+`color-error-border`枠のカード、`radius-md`
   - 文言(12px / 500 / `color-error`): 「ログインできませんでした。もう一度お試しください」
4. `OfflineNotice`(端末がオフラインのときのみ表示。`navigator.onLine`等での検知はfrontend-dev裁量)
   - 12px / `ink-muted`、ボタン群の直下: 「オフラインです。通信を確認してからログインしてください」
   - ログインボタン自体はグレーアウトせず表示は維持する(オフライン復帰後すぐ押せるようにするため)。タップ時にオフラインなら`OfflineNotice`と同じ文言をボタン直下に出す(ログインエラーとは別枠で表示、S2のバリデーション表示と同様に即時反映)

### LoggedInSection(ログイン済み状態)

1. `AccountStatusRow`(カード化はせず地の文で置く)
   - 見出し(16px / 900 / `ink`): 「アカウント」
   - ログイン中プロバイダ(13px / `ink-sub`): 「Xでログイン中」または「Googleでログイン中」
2. `MigrationStatusCard`(`paper-surface`背景、`paper-border`枠、`radius-lg`、`space-4`パディング。**移行対象データが無い場合はカードごと非表示**)
   - ラベル(`text-label`: 13px/700 / `ink-label`): 「データ移行」
   - 状態行(`text-body-sm`: 13px/500)。内容は「状態」の節を参照
   - 移行中のみ進捗バー(高さ10px、溝`paper-track`+`paper-track-border`枠、塗り`sakura`、`role="progressbar"`。S3a持ち物タブの準備状況バーと同仕様)
   - 失敗時のみ「再試行」ボタン(白地+`sakura-border`枠+`sakura-ink`文字、S1「再読み込み」ボタンと同仕様)
3. `LogoutButton`
   - 全幅、高さ48px以上、`radius-btn`、白地(`paper-surface`)+`paper-border`枠+`ink-strong`の中太文字
   - 確認ダイアログは出さない(ログアウトしてもクラウド上のデータは消えないため。`window.confirm`を使わない既存方針とも整合)

### LegalLinks(共通、常時表示)

S1フッターと同じ配置・文言。横並び、`space-6`間隔、`text-caption`(12px)/`ink-muted`。

## 状態

| 状態 | 表示 |
|------|------|
| 未ログイン・初期 | `LoggedOutSection`表示。`LoginErrorNotice`・`OfflineNotice`は非表示 |
| ログイン処理中(ボタンタップ〜外部リダイレクトまでの一瞬) | タップされたボタンを「◯◯に移動しています…」+スピナーの無効表示にし、もう一方のボタンも二重タップ防止のため無効化する。外部サイトへ遷移するため長時間は表示されない想定 |
| ログイン失敗(コールバックからエラーで復帰) | `LoggedOutSection`+`LoginErrorNotice`表示 |
| オフライン・未ログイン | `LoggedOutSection`+`OfflineNotice`表示。ボタンは押下可能だが押すと同じ文言をその場に表示する |
| ログイン済み・移行対象なし(元々ゲストしおりが0件だった) | `LoggedInSection`表示。`MigrationStatusCard`は非表示 |
| ログイン済み・移行中 | `MigrationStatusCard`表示。状態行「しおりを移行しています…」+件数「3/5件」、進捗バーが進む |
| ログイン済み・移行完了 | `MigrationStatusCard`表示。状態行「移行が完了しました」(`sakura-ink`)+補足「これからはクラウドに自動保存されます」(`ink-sub`)。進捗バー・再試行ボタンは非表示 |
| ログイン済み・移行一部失敗 | `MigrationStatusCard`表示。状態行「一部のデータを移行できませんでした」(`color-error`)+補足「電波の良い場所でもう一度お試しください」(`ink-sub`)+「再試行」ボタン表示 |
| ログアウト処理中 | `LogoutButton`を「ログアウトしています…」+無効表示に変える |
| オフライン・ログイン済み(移行中でない場合) | ログアウトボタン自体は端末内セッションのクリアのため通信不要で動作する想定。移行状態カードのみ「再試行」ボタンをタップした場合に限り上記`OfflineNotice`と同じ文言をカード内に表示する |

## タップ時の挙動

| 要素 | 挙動 |
|------|------|
| 戻るボタン | 直前の画面(通常はS1)へ戻る |
| Xでログインボタン | X (Twitter) OAuthを起動する。タップ直後は両ボタンを無効化しローディング表示にする |
| Googleでログインボタン | Google OAuthを起動する。挙動は上記Xと同様 |
| ログアウトボタン | ログアウト処理を実行する。確認ダイアログは出さない。完了後は`LoggedOutSection`表示に戻る |
| 再試行ボタン(移行失敗時) | 失敗した分の移行処理を再実行する。実行中は進捗バーが再度表示される |
| 利用規約リンク | `/terms`へ遷移 |
| プライバシーポリシーリンク | `/privacy`へ遷移 |

## 遠征当日の利用シーン確認

- S6は遠征準備・帰宅後に一度触る程度の画面で、当日その場で頻繁に使う想定はしていない(F8のログイン促しタイミングもしおり保存後・共有画像生成後の2箇所のみで、S6自体は導線の終点)
- 片手操作: ボタン類はすべて全幅・高さ48px以上でタップ領域を確保。縦一列配置のため片手の届く範囲で完結する
- 移動中/電波弱い: ログイン・ログアウト・データ移行はいずれも通信が必要なため、オフライン時は`OfflineNotice`で明示する。利用規約・プライバシーポリシーの閲覧(`/terms` `/privacy`は静的ページ)はオフラインでもキャッシュがあれば見られる(PWAのキャッシュ範囲は`docs/01_service_spec.md` F10の対象外のため保証はしない)

## 不明点・仮置き(完了報告にも記載)

- ルーティングを`/settings`とした。仕様(`docs/01_service_spec.md`)にS6のパス名指定が無いため仮置き
- S1ヘッダーへの設定導線(歯車アイコン)追加、およびS5「LoginHint」からS6へのタップ遷移追加は、S6の主要な入口として必要だが、本Issue(#92)の対象はS6画面自体の設計のみのためスコープ外とした。既存の`S1_ホーム一覧.md`・`S5_共有画像プレビュー.md`の改訂は別タスクが必要
- X/Googleログインボタンのアイコン(ロゴマーク)は各社のブランドガイドラインに基づく公式アセットであり、`docs/design/tokens.md`の「生の16進数を使わない」ルールの対象外とした(ボタン自体の背景・枠線・文字色はすべてトークンで指定)。特にGoogleの"G"ロゴは公式に4色構成のため、単色トークンでの代替はしていない
- ログイン失敗・オフライン時のエラー文言は汎用の1パターンのみとした(プロバイダ固有のエラー詳細・キャンセルと本当の失敗の区別は仕様に記載が無いため、実装が必要になった場合は#94 OAuthコールバック実装側と文言をすり合わせる)
- データ移行状態(移行中/完了/一部失敗)を渡すデータ構造は未定。`docs/03_tech_stack.md`の移行手順(テキスト一括INSERT→写真1枚ずつアップロード)を1つの進捗表示にまとめる設計としたが、実装時に#97〜#99のAPI・フロントオーケストレーション設計とすり合わせが必要
- ログアウト時に確認ダイアログを出さない判断は、他画面の「`window.confirm`を使わない」既存方針を踏襲した仮置き
- ログイン済みユーザーの表示名・アバター表示は行わない仮置き(仕様に明記が無く、追加のデータ取得スコープを避けるため。表示するのは「どのプロバイダでログイン中か」のみ)
