## 週次計画W28 タスク#4 S1/S2画面のUI設計

- Goal: S1(ホーム/一覧)とS2(しおり作成)の画面仕様がdocs/design/に揃い、frontend-devが実装に着手できる状態のPRが出ている
- 結果: 達成
- やったこと:
  - `docs/design/tokens.md` を新規作成。色・余白・角丸・タイポグラフィ・タップ領域のトークンをTailwind CSS v4(デフォルトパレット)へマッピング。カバー用プリセットカラー8色+絵文字8種のトークンも定義
  - `docs/design/screens/S1_ホーム一覧.md` を作成。空状態(ランディング兼用)/一覧状態(ShioriCard構造)/広告枠(F9)の位置確保のみ(W3まで中身未実装である旨を明記)/ローディング/読込エラー/オフラインの各状態、文言一覧、タップ挙動を記述
  - `docs/design/screens/S2_しおり作成.md` を作成。F1入力項目(タイトル/日程/遠征タイプ/目的/カバー)のコンポーネント構造、バリデーション文言(タイトル未入力・終了日<開始日等)、状態(初期/入力中/エラー/送信中/完了/オフライン)、文言一覧を記述
  - ルーティングは`/`(S1)、`/shiori/new`(S2)、作成完了後は`/shiori/[id]/packing`へ遷移する前提で記述(アーキテクト確定のルーティング方針に合わせた)
- できていないこと: なし
- 不明点・仮置き:
  - タイトル30文字/目的50文字の入力上限(仕様に数値記載が無いため仮置き。アーキテクト指示どおり仮置きである旨を明記)
  - カバー選択UIをプリセットスウォッチ8色+絵文字8種からの選択方式にした(自由な色ピッカー等の実装追加を避けるため。仕様に選択UI方式の指定は無い)
  - カバー未選択時の既定値を`cover-color-1`(`color:#F472B6`)に自動採用する仕様にした(仕様に既定値の記載が無いため)
  - カバーの色/絵文字トグルを切り替えた際、選択状態をリセットする挙動にした(仕様に記載が無いため)
- 成果物: `docs/design/tokens.md`, `docs/design/screens/S1_ホーム一覧.md`, `docs/design/screens/S2_しおり作成.md`(PR番号は本文作成後に追記)
