## 週次計画W28 タスク#4 S1/S2画面のUI設計

- Goal: S1(ホーム/一覧)とS2(しおり作成)の画面仕様がdocs/design/に揃い、frontend-devが実装に着手できる状態のPRが出ている
- 結果: 達成
- やったこと:
  - `docs/design/tokens.md` を新規作成。色・余白・角丸・タイポグラフィ・タップ領域のトークンをTailwind CSS v4(デフォルトパレット)へマッピング。カバー用プリセットカラー8色+絵文字8種のトークンも定義
  - `docs/design/screens/S1_ホーム一覧.md` を作成。空状態(ランディング兼用)/一覧状態(ShioriCard構造)/広告枠(F9)の位置確保のみ(W3まで中身未実装である旨を明記)/ローディング/読込エラー/オフラインの各状態、文言一覧、タップ挙動を記述
  - `docs/design/screens/S2_しおり作成.md` を作成。F1入力項目(タイトル/日程/遠征タイプ/目的/カバー)のコンポーネント構造、バリデーション文言(タイトル未入力・終了日<開始日等)、状態(初期/入力中/エラー/送信中/完了/オフライン)、文言一覧を記述
  - ルーティングは`/`(S1)、`/shiori/new`(S2)、作成完了後は`/shiori/[id]/packing`へ遷移する前提で記述(アーキテクト確定のルーティング方針に合わせた)
- できていないこと: なし
- 不明点・仮置き:
  - タイトル30文字/目的50文字の入力上限(仕様に数値記載が無いため仮置き。アーキテクト指示どおり仮置きである旨を明記)
  - カバー選択UIをプリセットスウォッチ8色+絵文字8種からの選択方式にした(自由な色ピッカー等の実装追加を避けるため。仕様に選択UI方式の指定は無い)
  - カバー未選択時の既定値を`cover-color-1`(`color:#F472B6`)に自動採用する仕様にした(仕様に既定値の記載が無いため)
  - カバーの色/絵文字トグルを切り替えた際、選択状態をリセットする挙動にした(仕様に記載が無いため)
- 成果物: `docs/design/tokens.md`, `docs/design/screens/S1_ホーム一覧.md`, `docs/design/screens/S2_しおり作成.md`(PR #19)

## 週次計画W28 タスク#5 S3(しおり詳細)画面のUI設計

- Goal: S3(しおり詳細タブシェル)/S3a(持ち物)/S3b(TODO)の画面仕様がdocs/design/に揃い、frontend-devが実装に着手できる状態のPRが出ている
- 結果: 達成
- やったこと:
  - `docs/design/screens/S3_しおり詳細.md` を作成。ヘッダー+5タブ(持ち物/TODO/旅程/スポット/ログ)の共通シェル構造、旅程/スポット/ログタブの「準備中」表示(ComingSoonブロック)、しおり未検出時の表示を記述
  - `docs/design/screens/S3a_持ち物.md` を作成。一覧(チェック/ラベル/上下矢印での並べ替え/編集/削除)、手動追加フォーム、空状態+「テンプレから追加」ボタンを記述。テンプレ自動投入は「初回のみ・全削除後は自動再投入しない」というアーキテクト確定仕様を反映し、実装上「テンプレ投入済みフラグ」が別途必要になる旨を明記
  - `docs/design/screens/S3b_TODO.md` を作成。期限日(任意)入力、期限が近い順ソート(期限なしは末尾)、期限当日の強調表示(`color-due-today-*`トークン使用)、テンプレ投入は持ち物タブと同パターンで記述
  - 並べ替えUIは上下矢印ボタン方式(D&Dライブラリ未追加)で統一。持ち物・TODOとも通常モード/並べ替えモードの2モードに分け、誤操作を防ぐ構造にした
- できていないこと: なし
- 不明点・仮置き:
  - 手動追加項目の文字数上限30文字(仕様に数値記載が無いため、S2のタイトル上限と揃えて仮置き)
  - TODOで完了済み項目を末尾へ移動しない扱い(仕様に完了項目の並び替え記載が無いため、位置は変えず見た目のみ変更する仕様にした)
  - TODOの期限切れ(過去日・未完了)項目への特別な強調は行わない扱い(仕様は「当日の表示強調のみ」のため)
  - F3テンプレートは遠征タイプに依らず共通1種として扱った(F2は遠征タイプ別テンプレのため差異がある。仕様にF3のテンプレを遠征タイプ別にする記載が無いため)
  - 削除操作をインライン確認(2段階タップ)方式にした(モーダルを使わず遠征当日の片手操作を優先する意図。仕様に削除確認UIの指定は無いため仮置き)
- 成果物: `docs/design/screens/S3_しおり詳細.md`, `docs/design/screens/S3a_持ち物.md`, `docs/design/screens/S3b_TODO.md`(PR #21)
