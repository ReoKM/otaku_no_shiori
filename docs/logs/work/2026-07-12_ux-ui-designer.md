  - スポットの一覧順は「追加順」とした仮置き(F5仕様に並べ替え・ソート順の記載が無いため)
  - カテゴリバッジの日本語表示名(聖地/会場/グルメ/グッズ/その他)は`seed-spot`スキルのcategory値(venue/seichi/food/goods/other)への仮訳

## 10:40 S4(スポット検索)画面のUI設計
- Goal: S4(スポット検索)の画面仕様がdocs/design/screens/に揃い、frontend-devが実装に着手できる状態のPRが出ている
- 結果: 達成
- やったこと:
  - `docs/plans/2026-W29.md`タスク#2・Issue #34、`docs/01_service_spec.md`F5、`.claude/skills/seed-spot/SKILL.md`(シードJSONスキーマ: name/description/category/area/map_query/source/caution/refs)を確認
  - 一覧画面(`/shiori/[id]/spots/search`)と詳細画面(`/shiori/[id]/spots/search/[spotId]`)の2段構成で設計。検索バー(名前・エリア・description部分一致、リアルタイム絞り込み)+カテゴリフィルターチップ(単一選択、6種)+結果件数+SpotCard一覧を定義
  - 一覧の並び順は仕様に指定が無いため「カテゴリ順(venue→seichi→food→goods→other)→名前順」で仮置きし、完了報告に明記
  - `description`(オタク文脈)は一覧で2行省略・詳細で全文表示、`caution`は一覧で「⚠ 注意あり」ラベルのみ・詳細で全文表示、という表示位置分担を定義
  - 状態(ローディング/初期/入力中/検索結果0件/完了/詳細表示中/追加処理中/追加済み/オフライン)・タップ挙動・文言一覧を整理。検索結果0件時はS3cの自由入力フォームへ戻れる導線を追加
  - `docs/design/screens/S4_スポット検索.md`を作成し、ブランチ`w2/task2-s4-design`(base: `w2-integration`)でPR化。同ブランチに本作業ログも含めた
- できていないこと: なし
- 不明点・仮置き:
  - 一覧の並び順「カテゴリ順→名前順」は完了条件どおり仮置き(上記参照)
  - 検索対象フィールド(名前・エリア・description)は仕様に指定が無いため仮置き
  - description・cautionの表示位置(一覧は要約、詳細は全文)は仕様に指定が無いため仮置き
  - 「しおりに追加」後はS4内に留まり「追加済み」表示にするのみとし、S3cへの自動遷移は行わない仮置き(連続して複数スポットを追加しやすくするため)
  - S4からの追加取り消し操作は用意せず、削除操作はS3c側に一本化する仮置き
  - `refs`(出典URL)はユーザー向け画面には表示しない仮置き(運営向け出典情報のため)
- 成果物: PR #51、`docs/design/screens/S4_スポット検索.md`
