## ハンバーガーメニューの表示方向変更+旅程「地図で見る」導線の常設化(オーナーFB対応)

- Goal: オーナーから本番相当のNetlifyプレビューを見た上でのFB2件(ハンバーガーメニューをサイドから出す/旅程の場所表示を「地図で見る」タップ導線に変える)を反映する
- 結果: 達成
- やったこと:
  - FB1(メニューの出方): `src/components/common/SideDrawer.tsx`を新規作成(右からスライドインする共通ドロワー。既存の`BottomSheet`(下からのシート)と同じ暗幕タップ・Escキー・背面スクロール停止・フォーカス移動のロジックを踏襲し、アニメーション方向だけ変更)。`src/app/globals.css`に`@keyframes paper-drawer-in`(`translateX(100%)`→`0`)を追加。`AppMenu.tsx`を`BottomSheet`→`SideDrawer`に差し替え
  - FB2(旅程の地図導線): `src/components/itinerary/EntryRow.tsx`の通常表示行(`mode==="view"`)で、これまで「📍場所名」をただのテキストとして表示していた行を「地図で見る」というタップ可能なリンク(`buildGoogleMapsSearchUrl`、新規タブで開く)に変更。既存の編集モード内の「地図で見る」リンク(既に実装済みだった)と同じ関数を再利用した
    - 行全体が「タップで編集開始」の`<button>`だったため、リンクをネストできない(HTML仕様上`<button>`内に`<a>`は不可)。行の要素を`<button>`から`role="button" tabIndex={0}`の`<div>`に変更し、Enter/Spaceキーでも編集開始できるようキーハンドラを追加。地図リンクは`onClick={(e) => e.stopPropagation()}`で行全体のクリックに食われないようにした
  - 動作確認: 本番ビルド+Playwright(375px)で、(1)メニューが画面右からスライドインし、ドロワーの右端が画面右端に一致すること、(2)旅程の予定行に「地図で見る」リンクが表示され、正しいGoogle Maps検索URLを持つこと、(3)そのリンクをタップしても行の編集モードに入らない(`stopPropagation`が効いている)ことを確認
  - `npm run lint && npm run typecheck && npm test && npm run build`すべて成功(523件全通過)
- できていないこと:
  - `SideDrawer`のコンポーネント単体テストは追加していない(このリポジトリの既存方針(`.tsx`は単体テスト対象外)に倣った。lint/typecheck/build+実ブラウザ確認で担保)
  - S3のログ/持ち物/TODOタブなど、他画面に同種の「場所を地図で見る」導線があるかは今回未調査(旅程タブのみ対応)
