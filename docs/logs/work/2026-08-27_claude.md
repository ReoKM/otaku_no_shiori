## 20:10 ログイン動線修正(OAuth成功後にトップページへ自動遷移)

- Goal: Googleログイン完了後、戻る操作をしなくてもトップページへ自動遷移し、Googleアカウント選択画面へ迷い込む不具合が起きない状態でPRがマージ可能になる
- 結果: 達成
- やったこと:
  - オーナー報告(動画添付): ログイン→Google認証→ログイン完了画面(`/settings`)→戻る、をするとブラウザ履歴上のGoogle側ページ(アカウント選択画面)へ戻ってしまう不具合を確認
  - 原因調査: `SettingsHeader`の戻るボタン(`BackButton`)は既定で`router.back()`のみを呼んでおり、OAuthの多段階リダイレクト(Googleアカウント選択→同意画面→`/auth/callback`→`/settings`)がブラウザ履歴に複数エントリを積むため、`戻る`操作でGoogle側のキャッシュされたページに着地してしまうことを確認(ブラウザ標準の挙動でありJS側から他ドメインの履歴エントリを削除する手段は無い)
  - 対策: 「戻る操作自体を不要にする」方針で実装。OAuthログイン開始時のリダイレクト先(`src/lib/supabase/oauth-login.ts`)に`justLoggedIn=1`の印を追加し、`/settings`側(`SettingsRoute`)でログイン成功を確認できたら約0.6秒後に`router.replace("/")`でトップページへ自動遷移するようにした(`router.replace`のため履歴に`/settings`を残さない)
  - 判定ロジックは`src/lib/post-login-redirect.ts`に`shouldAutoRedirectToHome`として切り出し、ユニットテスト4件を追加(オーナー報告の再発防止として、判定条件を明示的にテストで固定)
  - `justLoggedIn=1`が無い場合(既にログイン済みの状態で`/settings`を手動で開いた場合)は自動遷移しないようにし、アカウント確認・ログアウト目的のアクセスを妨げないようにした
  - `oauth-login.ts`のリダイレクト先変更に伴い`oauth-login.test.ts`の期待値を更新
  - `docs/design/screens/S6_設定アカウント.md`の「状態」表・「不明点・仮置き」に今回の自動遷移仕様を追記(実装と仕様のズレを残さないため)
  - `npm run lint` / `npm run typecheck` / `npm run test`(527件)すべて通過を確認
- できていないこと:
  - 実プロバイダ(Google/X)での実際のOAuth往復・戻る操作の動作確認はこの環境では実施できない(ブラウザでの対話的なOAuth同意操作が必要なため)。Netlifyプレビューデプロイ上でオーナーによる動画と同じ手順の再確認が必要
  - データ移行(`MigrationStatusCard`)の進捗を最後まで画面上で見せたいケースでは、0.6秒後の自動遷移により進捗表示が見えなくなる場合がある(移行処理自体はページ遷移後もバックグラウンドで継続するため、移行の成否には影響しない想定)。この体験でよいかはオーナー確認事項として完了報告に明記
- 不明点・仮置き:
  - 自動遷移の遅延時間(0.6秒)・遷移先(トップページ固定)は仕様に明記が無いための実装判断
  - 移行進捗中でも自動遷移を待たない仕様とした(「ログイン完了後は即トップページへ」という報告内容を優先。移行進捗を最後まで見せたい場合は要相談)
