# 週次計画 2026-W29(W2: 遠征体験+共有)

対象ロードマップ: [02_roadmap.md](../02_roadmap.md) Phase 1 / W2マイルストーン
> W2: 遠征体験+共有 — 旅程(F4)/スポット(F5、シードデータ最小投入)/写真とログ(F6)/共有画像生成(F7)が動く

## 前提

- W1(基盤+F1/F2/F3ゲスト保存)はmainにマージ済み。デプロイプレビュー確認済み(PR #26〜#31)。Supabase接続情報(URL/anonキー)はNetlify環境変数に登録済みだが、**マイグレーション適用はまだ**(オーナー作業)。ログイン(F8)はW3スコープのため、W2は引き続きゲスト保存のみで完結する設計を維持する。
- ゲスト保存基盤`src/lib/guest-store.ts`はDB_VERSION 1でshiori/packing_items/todosの3ストアのみ。W2実装の前提として、itinerary_entries/shiori_spots/photos(Blob)ストアを追加するDB_VERSION 2への拡張が必要。
- 2026-07-11オーナー決定により、スポット(F5)は独立タブではなく旅程タブ(S3c)内のセクションとして扱う。旅程タブ内の具体的な構成(旅程とスポットの並び順・切替UI)はW2のUI設計タスクで確定する。
- 前週計画は[2026-W28.md](./2026-W28.md)。W1のGitHub Issue(#3〜#13)はまだOPENのまま(タスク自体はマージ済みだが未クローズ)。本計画のスコープではないため個別にはクローズせず、気付いた点としてのみ記載する。
- 「遠征/近場の区分」はオーナーが「このあと検討」としているため、本計画のタスクには含めない(オーナー検討が済み次第、次週以降の計画で扱う)。

## 今週のゴール

1. **旅程とスポットが1つのタブ(S3c)で動く**(W2マイルストーン「旅程(F4)/スポット(F5)」に対応): 日ごとのタイムライン追加・編集・削除・並べ替え、Googleマップリンク自動付与、シードスポット検索からの旅程/しおりへの追加が、ゲスト保存で一通り使える状態にする。
2. **写真とログ(F6)が動く**(W2マイルストーン「写真とログ(F6)」に対応): 日付に紐付けた写真+ひとことメモの記録が、クライアント側リサイズ(長辺1600px)・20枚上限付きでゲスト保存される状態にする。
3. **共有画像生成(F7)が動く**(W2マイルストーン「共有画像生成(F7)」に対応): しおり内容から縦長(1080×1920)画像をNetlify Functions(satori+resvg)で生成し、プレビュー→端末保存ができる状態にする。ロゴ+URLを画像内に必ず含める。

## オーナー判断が必要な事項

1. **シードスポットのデータソース**。F5の実装(タスク9)はデータの持ち方で作業内容が変わる。
   選択肢A: アプリ内蔵JSONバンドル(`seeds/spots/`のJSONをビルド時に静的インポート。ゲストでもオフラインでも検索できる)。
   選択肢B: Supabaseの`spots`テーブルから取得(マイグレーション適用+クライアント側フェッチ実装が前提)。
   推奨: A。理由: W2はログイン機能(F8)がまだ無くゲスト保存のみで完結する設計のため、DB接続を前提にするとマイグレーション未適用というブロッカーに引っかかる。JSONバンドルなら今週中に完結でき、Phase 2でDB移行する際もシードJSONをそのままSQLの初期データとして流用できる。
   ※本計画のタスク9・後続はこの推奨Aを前提に設計している。選択肢Bを選ぶ場合は、マイグレーション適用(オーナー作業)+backend-devによる`spots`取得APIまたはクライアント実装の追加タスクが必要になり、今週中のF5完了は難しくなる見込み。

2. **Supabaseマイグレーション適用のタイミング**。W1で作成済みのマイグレーションSQL(`supabase/migrations/0001_initial_schema.sql`)はまだ実プロジェクトに未適用。
   選択肢A: 今週も未適用のまま進める。
   選択肢B: 今週中に適用しておく(判断1で選択肢Bを選ぶ場合は必須)。
   推奨: A。理由: W2はゲスト保存のみで完結する設計であり、判断1でAを選ぶ場合は適用を急ぐ理由がない。W3のF8(ログイン)着手直前に適用すれば間に合う。

3. **共有画像のデザイントーン**。F7の「シンプル/にぎやか」2テンプレは仕様上名称と内容要件のみで、具体的な配色・情報密度の指定が無い(タスク7で仮置きが発生する箇所)。
   選択肢A: share-image-designerが初稿(2テンプレ)を作成し、PRでオーナーがレビューして方向性を確定する。
   選択肢B: 着手前にオーナーが色数・写真の扱いなど方向性を指定し、それに沿って実装する。
   推奨: A。理由: MVPの原則(`docs/01_service_spec.md`「迷ったら削る」)に沿い、まず動くものを見てから調整する方がスピードを優先できる。W2内でのフィードバック→修正の1往復は許容範囲。
