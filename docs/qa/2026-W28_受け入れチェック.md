### NG-1(重要): 持ち物タブを初めてリロードすると、持ち物一覧が重複する

- **概要**: しおり作成直後、持ち物タブを初めてリロードすると、自動投入されたテンプレ項目が2件ずつ重複表示される
- **再現手順**:
  1. しおりを新規作成する(例: 遠征タイプ「ライブ/イベント参戦」)
  2. 持ち物タブが開き、テンプレ8件(チケット/ペンライト/うちわ/推しタオル/トレカケース/モバイルバッテリー/双眼鏡/銀テ入れ)が自動投入された状態で表示される(この時点では8件、正常)
  3. ブラウザをリロードする(F5 / `location.reload()`)
- **期待/実際**: 期待: 引き続き8件のまま / 実際: 16件(各項目が2件ずつ)になる
- **再現性**: 検証環境(`npm run dev`)で複数回・複数の新規しおりで100%再現。2回目以降のリロードでは追加の重複は発生しない(8→16→16で安定)
- **原因の手がかり(推測)**: `src/components/packing/PackingTab.tsx`の`useEffect`は、テンプレ未投入判定(`!isPackingTemplateSeeded`)を通過した後の`seedPackingTemplate`呼び出しの前に、effectのキャンセル状態(`cancelled`)をチェックしていない。一方`src/components/todo/TodoTab.tsx`は`listTodosByShiori`取得直後に`if (cancelled) return;`を入れており、同種の重複は起きない(実際にF3側は同じ手順で重複しないことを確認済み)。開発サーバーのReact Strict Mode/Fast Refreshによるeffect二重実行が疑われる。TodoTab側の実装と同様の早期returnガードを検討されたい
- **環境・重要度**: ゲスト利用(`npm run dev`)・スマホ幅375px / **重要度: 高**(コア機能である持ち物リストのデータが実際に重複作成され、IndexedDBに恒久的に残る。ユーザーが最初に行う操作=作成後の画面リロードで発生するため遭遇率が高い)
- **Issue**: #25
