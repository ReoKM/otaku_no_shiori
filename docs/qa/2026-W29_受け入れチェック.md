確認方法:
- F4/F5/F6・S5画面の状態遷移: `npm run dev`(開発サーバー)+ Playwright(検証用に一時インストール。リポジトリには含めない)+ 375px幅ビューポート
- F7の実画像生成: `npx netlify-cli dev`はサンドボックス環境でEdge Functionsの取得が403(プロキシ経由の外部通信不可)になり起動不可だったため、`netlify-cli functions:serve`で`netlify/functions/share-image.mts`のみを起動し、`curl`で`/api/share-image`へ直接POSTしてPNGを取得・目視確認した。S5画面側は(Function未接続の`npm run dev`環境のため)生成失敗フォールバック表示の確認に切り替えた
- 写真アップロード: Playwrightの`setInputFiles`でNode.jsスクリプト生成したダミーPNG(1x1・200x200単色)を使用

## スコープ

- Supabase実環境・Netlifyプレビューデプロイでの確認: 対象外(次回mainマージ後に別途)
- 自動E2E環境の恒久構築(`e2e/*.spec.ts`の追加): 対象外。W1受け入れチェック(`docs/qa/2026-W28_受け入れチェック.md`)と同様、本タスクの完了条件は「チェックリスト作成+手動実行」であり、依頼手順の「やらないこと」にも「playwright/netlify-cli関連ファイルのコミット」が明記されているため、Playwrightは検証用に一時利用したのみでリポジトリには追加していない
- しおり削除(丸ごと削除)によるカスケード確認: S1一覧に削除UIが未実装(F1〜F10のいずれにも「しおり削除」機能の明記なし)のため、UIからの確認は対象外。ただし`guest-store.ts`の`deleteShiori`のカスケードロジック自体は、そのロジックをブラウザのIndexedDB APIで再現し動作確認した(下記「横断確認」参照)
